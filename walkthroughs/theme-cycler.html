theme-cycler.ts

用快捷键（Ctrl+X 向前、Ctrl+Q 向后）和 /theme 命令切换主题，切换后在状态行写主题名、在编辑器下方闪 3 秒色块。181 行，订阅 session_start 和 session_shutdown，注册 2 个快捷键、1 个命令。这一篇第一次用到 pi.registerShortcut：入口是键盘，既不经过 prompt()，也不进双循环。
运行：just ext-theme-cycler（同时加载 minimal）

    至此走读里出现了扩展的三种入口：pi.on 由 Pi 在固定时点调用；registerCommand 在用户提交 /名字 时由 prompt() 调用；registerShortcut 在编辑器收到按键时调用，ctx 由交互模式现场拼出来（interactive-mode.ts:2248），每次按键都是新的一份。源码链接指向 Pi 1.4.0（4a08025）的 TS 源码。

    ① 四层结构

    第 1–7 步是启动链：快捷键在加载时只是登记，等交互模式绑定扩展时才和内置快捷键比对，冲突的被跳过。第 8–14 步是一次 Ctrl+Q：从 L4 的编辑器直接到 L3，改主题时又穿到 L1 的设置文件，最后回到 L4 全屏重绘。

    ② 提示词上下文

    theme-cycler 不在安装、控制、装配任何一段：主题只影响终端怎么画，LLM 完全不知道。快捷键连文字都不产生，/theme 在 input 之前被截走，也不会变成 user 消息。它影响的是另一条“上下文”：全局设置文件。每切一次主题，settings.theme 就写一次盘，所有项目、所有 Pi 会话共享。

    ③ 业务穿透

    模拟器有两部分。上半部分复刻 runner.getShortcuts 的冲突判定，用的是 Pi 1.4.0 在 macOS 上的默认快捷键表：输入一个键，看扩展注册它会被跳过、覆盖内置功能，还是空闲可用。下半部分复刻 cycleTheme（第 82–105 行），主题列表按 Pi 的排序（system 在前，其余按字母）。

    近似之处：快捷键表取的是 macOS 默认值（Windows 上 ctrl+q 是排队 follow-up，属于保留键）；用户在 keybindings.json 里改过的键不在其中。主题列表用的是本仓库 .pi/themes（HEAD）加内置主题，家目录下的自定义主题不算。

    Bug：Ctrl+X 和 Pi 的保留快捷键冲突，被直接跳过。Pi 1.4.0 把 ctrl+x 分配给 app.message.copy（复制上一条回复，keybindings.ts:64），而这个动作在保留名单里（runner.ts:110）。getShortcuts 遇到保留键时记一条 “conflicts with built-in shortcut. Skipping.” 然后 continue（runner.ts:697）。结果是文件头和第 109 行承诺的“Ctrl+X 向前切换”从来不生效，按下去执行的是复制；只剩 Ctrl+Q 向后切换。在 Windows 上 ctrl+q 是排队 follow-up，也是保留键，两个快捷键都没了。修法：换一个不在默认表里的键（可以用 /hotkeys 查），并同步改文件头注释。注意别换成编辑器在用的非保留键（例如 ctrl+a 是行首）：那种情况扩展会胜出并给出警告（runner.ts:705），原来的编辑功能就没了。模拟器里输入键名可以逐个试。
    切换的结果会被 themeMap 在下次 session_start 改回去。每次切换都写全局 settings.theme，看起来会“记住”。但第 171 行的 applyExtensionDefaults 在每次 session_start（启动、/reload、/new、/resume）都按 themeMap 设主题：just ext-theme-cycler 里本扩展是第一个 -e，于是每次都被改回 synthwave，并且再写一次设置文件。只有当别的扩展排在前面时，本扩展的 applyExtensionDefaults 才什么都不做（同样会被那个扩展的主题覆盖）。场景 B 演示了 /reload 之后的变化。另外设置文件是全局的：在这里切主题，会影响其他项目里下一次启动的 Pi。
    和 minimal 一起用，状态行看不到。本扩展的 setStatus("theme", …) 写法是对的（对比第 05 篇少传 key 的写法），但扩展状态只由内置页脚绘制（footer.ts:290）。just ext-theme-cycler 同时装了 minimal，它用 setFooter 换掉了内置页脚，于是 “🎨 名字” 永远不显示，只能靠 notify 和色块知道当前主题。这是页脚槽位的取舍，不是本扩展写错。
    小处。闭包变量 currentCtx（第 25 行）被赋值了 4 次，从来没被读过。/theme 的列表里，t.path ? t.path : "built-in" 只有 system 主题会显示 “built-in”：内置的 dark / light 也有文件路径（theme.ts:418）。当前主题不在列表里时（第 92 行）index 取 0，再 ±1，第一个主题会被跳过。色块定时器在 session_shutdown 里清掉，避免旧 ctx 在会话切换后还被调用，这是值得照抄的写法。

    小结

    theme-cycler 补齐了扩展的第三种入口：registerShortcut。按键在编辑器里就被拦下，handler 拿到现拼的 ctx，和 /theme 命令一样完全在双循环之外。它改的是渲染和全局设置，不碰 LLM 上下文；它最大的坑也在入口处：Ctrl+X 撞上了 Pi 的保留键，在绑定阶段就被静默跳过（只在启动时的 Extension issues 里留一条警告）。下一篇 system-select.ts 回到循环：在 before_agent_start 改系统提示词，第一次真正改动“安装”这一段。
