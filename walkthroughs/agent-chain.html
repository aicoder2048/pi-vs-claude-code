agent-chain.ts

把几个子 agent 串成固定的流水线（定义在 .pi/agents/agent-chain.yaml）：主 agent 调一次 run_chain，扩展依次起每一步的 pi 子进程，上一步的输出替换进下一步提示词里的 $INPUT。797 行，订阅 session_start、before_agent_start，注册 1 个工具、2 个命令。和第 13 篇的区别：主 agent 保留自己的工具，子进程是串行的，数据在步骤之间流动。
运行：just ext-agent-chain（同时加载 theme-cycler）

    ① 四层结构

    第 1–5 步是启动链：载入流水线，但卡片要等第一次提问才挂上。第 6–14 步是一次 run_chain：L3 的 runChain 是一个 for 循环，每一圈都穿到 L1 起一个子进程，再把它的输出带回 L3 填进下一步的模板。

    0 / 14
    按“下一步”开始。第 1–5 步在循环外；第 6 步起是主进程工具阶段里的一次 run_chain。

    ② 提示词上下文

    agent-chain 的提示词工作分两层。主进程：before_agent_start 整个替换系统提示词（同第 13 篇，没接 event.systemPrompt），但工具没收走，所以工具声明还在，丢掉的是默认提示词里关于工具用法的说明、项目上下文和 skills。子进程之间：每一步的 user 消息由 YAML 模板拼出来，$INPUT 是上一步的全部输出，$ORIGINAL 是主 agent 传给 run_chain 的 task（不一定是用户原话）。

    Bug：$INPUT 替换把上一步的输出当成替换模板。第 470 行 .replace(/\$INPUT/g, input) 的替换值是字符串，JS 会解释其中的 $$、$&、$`、$'（和第 08 篇 cross-agent 同一类问题）。子 agent 的输出里经常有 $：shell 的 $$、价格、LaTeX 的 $$…$$，下一步收到的就被改过了。第 471 行又在替换后的结果上找 $ORIGINAL，上一步输出里如果提到了这个占位符，也会被换掉。修法：step.prompt.replace(/\$(INPUT|ORIGINAL)/g, (_, k) => k === "INPUT" ? input : originalPrompt)，一次替换、用函数取值。模拟器默认的输出里就带 $$5。
    Bug：按 Esc 停不下流水线，剩下的步骤会全部跑完。和第 13 篇一样，第 516 行丢掉了 _signal，runAgent 不会 kill 子进程。这里更糟：runChain 的 for 循环（第 464 行）也不检查中止，第 1 步跑完后照样起第 2、3 步。plan-build-review 里第 2 步是有写权限的 builder，用户按 Esc 想阻止的修改仍会发生。修法：把 signal 传进 runChain，每一步开始前检查 signal.aborted，并在 abort 时 kill 当前子进程。场景 B 演示了这个过程。
    Bug：页脚上下文条和第 01 篇同一个越界。第 780–781 行 Math.round(pct / 10) 没有上限，pct ≥ 105 时 "-".repeat(负数) 抛 RangeError。
    “输出”是整个子会话所有文字的拼接。第 391 行把每个 text_delta 推进 textChunks，从不在消息边界清空。子 agent 跑了 5 个 turn，$INPUT 就是 5 条 assistant 消息的文字首尾相接（“…I'll check the routes.The plan is:…”，中间没有换行），中途的自言自语也一起传给下一步。只想要结论的话，应该在 message_end 时只保留最后一条 assistant 消息的文字。第 13 篇 agent-team 的写法相同，同样有这个问题。
    同一成员出现多次，会共用一个会话。会话按成员名存（第 341–343 行）。scout-flow 连用三次 scout、plan-review-plan 两次用 planner，后面的步骤会 -c 续上前面的会话：自己上一步的输出已经在上下文里，又被当成 $INPUT 原样塞一遍，上下文翻倍。另一方面，“请复核下面的分析”这种指令，交给一个记得自己写过这份分析的 agent，复核效果也打折扣。模拟器里选 scout-flow 能看到每一步的 -c 标记。
    整个替换系统提示词，但工具没收。第 688 行没有拼 event.systemPrompt。和第 13 篇不同的是本扩展让主 agent 保留 read / bash 等工具，提示词里也鼓励它“简单的事自己做”，但 Pi 默认提示词里关于这些工具怎么用的说明、AGENTS.md 等项目上下文被一起换掉了（工具声明本身仍在，见第 10 篇的投影）。另外提示词里塞了每个成员的完整正文（第 683 行），流水线长时，主 agent 每个请求都要带着这些它并不执行的指令。

    小结

    agent-chain 和 agent-team 挂在同样的位置：before_agent_start 换提示词，一个工具在 run 内循环的工具阶段起子进程。区别在工具内部：runChain 是一个串行的 for 循环，每一圈起一个完整的子 settle，用字符串模板把上一步的文字交给下一步。数据只靠字符串在步骤之间流动，所以替换规则、输出怎么截取、会话怎么复用，都直接决定下一步看到什么。下一篇 pi-pi.ts 是“元 agent”：用同样的子进程手法，让一组专家 agent 帮你写 Pi 扩展。
