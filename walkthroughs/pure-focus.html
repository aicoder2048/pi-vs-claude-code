    ③ 业务穿透

    pure-focus 的核心逻辑只有 render() { return []; }，单独模拟没意思。真正有讲头的是它和别的扩展叠加时谁赢。下面用 JS 复刻了 pure-focus、minimal 的 render 和内置页脚（简化版），选一种 -e 组合试试。

    叠加时会吞掉别的扩展的状态行。just ext-subagent-widget 同时加载了 pure-focus 和 theme-cycler。theme-cycler 用 setStatus("theme", "🎨 …") 显示当前主题，但这一行只有内置页脚会画，而内置页脚已经被 pure-focus 摘掉，所以无论启动时还是用快捷键 / /theme 切主题，这行状态都看不到。在模拟器里选第二个组合就能看到。这算组合用法的问题，不是 pure-focus 代码写错：它的注释写的就是去掉 “status line”（setStatus 的类型注释也叫它 footer/status bar，types.ts:165）。
    注释里说的 “status line”指页脚第三行的扩展状态，不是 run 进行中的 Working 指示器。后者挂在 statusContainer，在组件树里排在编辑器上面（interactive-mode.ts:984），pure-focus 管不到它。勾选模拟器的“运行中”可以看到它还在。要连它一起去掉，得再调一次 ctx.ui.setWorkingVisible(false)（interactive-mode.ts:2363）。另外，文件头的用法写成了 pi -e examples/extensions/pure-focus.ts，本仓库的实际路径是 extensions/。

    小结

    pure-focus 和 minimal 是同一个模式：在循环外（session_start）用 setFooter 换掉 L4 的一个槽位，之后跟着 TUI 重绘被调用。区别是 minimal 每帧去 L2 拉 L1 的数据，pure-focus 什么都不拉。槽位只有一个，所以叠加扩展时是最后一个 setFooter 赢。下一篇 tool-counter-widget.ts，第一次订阅 run 内循环的事件。
