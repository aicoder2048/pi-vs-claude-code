pi-pi.ts

“造 Pi 的 Pi”：主 agent 负责写文件，遇到不懂的就调 query_experts，一次把问题并行派给几位领域专家（扩展、主题、skills、TUI……）。每位专家是一个没有会话的 pi 子进程，先抓最新文档再回答。633 行，订阅 session_start、before_agent_start，注册 1 个工具、2 个命令。前两篇的子进程一次一个；这一篇在一个工具调用里同时起多个。
运行：just ext-pi-pi（同时加载 theme-cycler）

    ② 提示词上下文

    主进程的系统提示词不写在代码里，而是每次 settle 时读 .pi/agents/pi-pi/pi-orchestrator.md，把 {{EXPERT_COUNT}} 等占位符换成实际的专家名单，再整个替换掉默认提示词（同第 13、14 篇，没接 event.systemPrompt）。主 agent 保留全部工具，是唯一负责写文件的。专家子进程没有会话，每次都从零开始：先按自己正文里的指令抓上游文档，再回答这一个问题。

    ③ 业务穿透

    模拟器复刻了 query_experts 的并行调度（第 407–473 行）和单个专家的重入检查（第 254–260 行）。勾选这一批要问的专家，可以让同一位专家出现两次，看哪些子进程真正启动、总耗时由谁决定、这条 toolResult 最多有多大。

    近似之处：每位专家的耗时是示意值（按领域给了不同的秒数）；字数按 12000 字上限估算，真实答案通常更短。

    Bug：按 Esc 停不下任何一个专家。第 407 行同样丢掉了 _signal（第 13、14 篇的同一个问题）。这里一次起的是 N 个进程，Esc 之后它们全部继续抓文档、调模型，主进程要等最慢的那个结束才收尾。修法：把 signal 传进 queryExpert，abort 时 kill 所有子进程。
    Bug：页脚上下文条和第 01 篇同一个越界。第 612–613 行 Math.round(pct / 10) 没有上限，pct ≥ 105 时 "-".repeat(负数) 抛 RangeError。
    找不到模板文件时，系统提示词只剩一句报错。第 564 行按 ctx.cwd 拼模板路径，读失败就把 systemPrompt 设成 “Error: Could not load pi-orchestrator.md…”（第 576 行），而且照样整个替换。不在项目根目录启动 Pi 时，主 agent 拿到的系统提示词就是这一行：没有角色、没有专家目录、没有 Pi 默认的工具说明。比较稳的做法是读失败时返回 undefined，保持默认提示词，并 notify 用户。
    专家每次都从零开始。--no-session（第 282 行）让每次查询都是一个全新的进程：文件头说“第一次查询时抓文档”，实际上每次查询都会按专家正文的指令重新抓一遍。另外文档来自上游仓库 main 分支，而本机是 Pi 1.4.0，专家讲的 API 可能比本机新；主 agent 照着写出来的扩展，需要以本机源码为准再核对一遍。
    “只读专家”只是约定。文件头写“Experts are read-only researchers. The primary agent is the only writer.”，但本仓库每位专家的 tools 都包含 bash（抓文档要用），有 bash 就能写文件。只读靠的是专家正文里的指令，不是工具清单。另外工具描述（第 377–389 行）列了 8 位专家，参数说明（第 397 行）只列了 7 位，目录里实际有 9 位（多出 cli-expert）；系统提示词里的目录是按实际加载的生成的，所以模型最终还是能看到全部。
    和其他扩展叠加。和第 13、14 篇一样整个替换系统提示词（没接 event.systemPrompt），排在前面的扩展加的提示词会被丢掉。第 572–574 行的 String.replace 用字符串作替换值，和第 08 篇是同一类写法；本仓库专家描述里出现的 $1、$@ 恰好不是 JS 的特殊模式，所以目前没出问题，但描述里一旦出现 $& 或 $$ 就会被改写。

    小结

    pi-pi 是第 13、14 篇子进程手法的第三种形状：一个工具调用内部并行起 N 个无会话的子进程，Promise.allSettled 等齐，再拼成一条结果交给负责写文件的主 agent。三篇放在一起看，挂点完全相同（before_agent_start + 工具阶段），差别只在工具内部怎么组织子进程：单个、串行、并行。下一篇 subagent-widget.ts 换一种方式：子代理在后台跑，结果用 sendMessage 送回主会话，不再卡住主 agent 的工具阶段。
