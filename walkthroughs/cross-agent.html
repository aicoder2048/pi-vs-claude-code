    ① 四层结构

    第 1–6 步是启动链：扫描和注册都在工厂函数里同步完成，session_start 只负责通知。第 7–15 步是一次 /prime：前半段和上一篇一样在 L1 入口被截到 L2；L3 展开模板后，经 L2 的 sendUserMessage 回到 L1，第二次进入 prompt()，这次一路走到 _startRun。

    ② 提示词上下文

    cross-agent 站在安装这一段：它不改系统提示词，而是把别的 agent 的命令文件当成一条 user 消息塞进上下文。和用户亲手输入的消息没有区别：同样经过 input 订阅者、同样落盘、之后每个 turn 都在请求里。模型看到的是展开后的全文，看不到 /prime 这几个字。

    来源怎么变成上下文和原工具里的语义差在哪
    commands/*.md正文展开参数后作为 user 消息frontmatter 里的 model、allowed-tools、argument-hint 都不生效；正文里的 !`命令`、@文件 之类写法原样发给模型（推断：Pi 不认这些语法，代码里也没有处理）
    skills/<name>/SKILL.md整份原文（含 frontmatter）作为 user 消息，后面接 Task: …没有告诉模型 skill 在哪个目录。SKILL.md 里的相对路径（比如本仓库 ext-walkthrough 的 references/source-anchors.md）会被当成相对于 cwd。Pi 自己的 /skill: 会写明 location 和 baseDir（agent-session.ts:2224）
    agents/*.md不进上下文只在启动通知里显示为 @name，没有任何调用方式

    Bug：agent 正在跑时执行这些命令会报错，消息丢失。上一篇讲过，扩展命令在 streaming 时也会立即执行。第 188、200 行的 pi.sendUserMessage(text) 没传 deliverAs，于是 prompt() 发现 isStreaming 又没有 streamingBehavior，抛出 “Agent is already processing. Specify streamingBehavior…”（agent-session.ts:2140）。:3458 把它转给 emitError，聊天区显示一条扩展错误（interactive-mode.ts:2037），展开好的命令内容不会排队。修法：pi.sendUserMessage(text, { deliverAs: "followUp" })，空闲时这个选项不起作用，在跑时会排到本次 settle 之后。场景 B 和模拟器都能复现。
    Bug：expandArgs 把用户参数当成替换模板。第 72、74 行用字符串做 replace / replaceAll 的替换值，JS 会解释其中的 $$、$&、$`、$'：参数里写 $$5 会变成 $5，写 $& 会变成 $ARGUMENTS。另外先替换 $ARGUMENTS 再替换 $1…，用户参数里的 $1 会被再替换一次；$1 也会命中 $10 的前两个字符，第 10 个参数永远取不到。修法：用函数形式 replace(re, () => args) 避开特殊模式，并一次性用 /\$(ARGUMENTS|@|\d+)/g 替换。模拟器的预设能逐个复现。
    Bug：启动通知的“… N more”算错了。第 274 行用 totalItems - 15，15 是个和实际显示无关的常数：前 3 行显示了多少项取决于终端宽度和名字长度。只有 16 项时显示 “1 more”，可能其实藏了 10 项；不到 15 项被截时显示 “more more”（"more" 后面又接了 " more"）。修法：统计前 3 行里出现的名字数，用总数减去它。
    注释说的“在 session_start 里注册会被静默丢掉”，在 1.4.0 里找不到依据。第 147–150 行说 registerCommand 必须在加载时同步调用。但 loader.ts:306 只做 assertActive，没有“加载阶段已结束”的检查；getCommand 每次都实时遍历 ext.commands。也许是旧版本的限制，或者补全列表不刷新（推断，未验证）。在工厂里同步注册本身没问题，只是理由不确定。另外用 process.cwd() 代替 ctx.cwd 的前提是“Pi 总在项目根启动”，不在根目录启动时就扫错地方。
    扫的目录不一定是那些工具真正放命令的地方。扫描对三个工具一视同仁：commands/*.md、skills/、agents/*.md。这是 Claude Code 的布局。按各工具的公开文档（页面外的知识，没有在本仓库验证），Gemini CLI 的自定义命令是 .gemini/commands/*.toml，Codex 的自定义提示在 ~/.codex/prompts/，这两处用 .md + commands/ 的规则大多扫不到。
    位置参数按空白切分。/plan_w_team build a login page：$1 是 build，$2 是 a，后面的词没有占位符可去，丢了。这个仓库的 plan_w_team.md 正是用 USER_PROMPT: $1 接一整句需求，在 Pi 里只剩第一个词。模拟器默认就是这个例子。

    小结

    cross-agent 把命令和 settle 连了起来：命令 handler 仍在循环外，但它调 pi.sendUserMessage，让 prompt() 再走一遍，这次走到 input 和 _startRun，双循环才开始转。它往上下文里放的是一条普通的 user 消息，所以其他扩展的 input 订阅者也能看到和改写它。下一篇 theme-cycler.ts 回到 UI：命令加快捷键切换主题，第一次用到 registerShortcut。
