L01 · 全景与双循环

边牧全景：羊、边牧与双循环

边牧是一个桌面应用。它让编码 agent 先列清单再动手，没做完不许停。这一课先建立全景：谁在哪个进程里，谁管什么，以及“停没停”由什么决定。

原文：§0–1阅读约 15 分钟含 2 个互动演示

学完本课，你能够：

  • 用边牧放羊比喻说出用户、AI、任务各是什么。
  • 说出 TillDone 和 PStack 各管什么，以及约束力的区别。
  • 画出边牧的进程结构，指出哪个进程不受 TillDone 管。
  • 解释为什么桌面端只把 agent_settled 当作空闲。

01边牧放羊

先说结论：边牧（TillDone Desk）是 apps/tilldone 里的 Electron 应用。它用桌面界面替代 Pi 的终端界面，来跑 TillDone 扩展。

项目给它取中文名“边牧”，来自一个比喻。这个比喻是项目唯一认可的映射。

羊
任务

清单里的每一项工作。羊要一只一只赶进圈。

边牧
装了 TillDone 的 AI

它负责赶羊。羊没进圈，它就不歇。

牧羊人
用户

牧羊人指方向。他可以指着一只羊，让边牧把它拆小。

口号羊不进圈，边牧不歇。英文是 Don't stop until it's done。

02两个扩展，两种职责

边牧的 Pi 子进程里加载两个扩展。TillDone 一直加载。PStack 是可选的，用 TILLDONE_PSTACK=1 启动时才加载。

TillDone：立规矩

  • 门禁：先列清单、认领一个任务，才许动手。
  • 督促：清单没做完，run 结束时催一次。

硬约束。模型绕不过去。

PStack：给做法

  • Playbook 和原则。
  • subagent 分派。
  • 按角色选模型。

软约束。只靠提示词引导。

本课程的核心句TillDone 管“做什么、做完没”，用硬约束守住。PStack 管“怎么做”，只靠提示词引导。

原文还有一个判断：两者在代码里只有三个接缝。“两份清单怎么配合”没有写进任何模型能看到的提示词。L06 会展开这一点。

常见误解讨论稿说“TillDone 是大脑，管任务拆解；PStack 是手脚，管落实执行”。原文认为这只对一半。TillDone 自己不拆任务，拆的决定由模型做出。详见 L06。

03进程全景

边牧不把 Pi 嵌进自己的进程。它用 RPC 模式起一个 Pi 子进程，用 JSONL 收发命令和事件。

子进程的命令行（src/config.ts:26-28）：

pi --mode rpc --no-extensions --model <model> -e <app>/extensions/tilldone
   [-e <cwd>/.pi/npm/node_modules/pi-pstack/extensions/pstack -a] [--session <file>]
  • --no-extensions 让全局扩展不加载。子进程里只有这两个扩展。
  • -a 信任工作目录里的项目本地文件。PStack 的技能需要它。

04Pi 的双循环

先说结论：Pi 有两层循环。TillDone 的督促利用外层循环“再转一圈”。所以“run 结束”不等于“停下来”。

外层
settle 外循环

源码在 AgentSession._startRun() 的 while。一个 run 结束后，如果有重试、压缩或排队消息，就再起一个 run。停稳时发出 agent_settled。

内层
run 内循环

源码在 agent-loop.js 的 runLoop()。它反复执行 turn。一个 turn 是一次 LLM 请求，加上这条回复里所有的工具调用。

  • 用户一句话 = 一次 settle。
  • 一次 settle 通常只有 1 个 run。督促发生时有 2 个 run。
  • 督促每条用户输入最多一次。所以 run 数不超过 2。

督促的路径是这样的。run 1 结束时，TillDone 的 agentEnd 检查清单。如果还有未完成任务，它发一条 tilldone-nudge 消息。这时 run 仍算活跃，所以消息进入 steer 队列。外循环看到排队消息，就再起 run 2。

本节核心句桌面端只把 agent_settled 当作“空闲”。agent_end 不算空闲，因为督促可能让外循环再转一圈。

    06自测与速记

    在边牧的比喻里，“牧羊人”指什么？
    任务是羊，装了 TillDone 的 AI 是边牧，用户是牧羊人。
    下面哪一项最准确地描述了 TillDone 和 PStack 的分工？
    原文 §0：TillDone 管“做什么、做完没”，用硬约束守住。PStack 管“怎么做”，只靠提示词引导。TillDone 自己不拆任务。
    桌面端为什么不把 agent_end 当作空闲？
    run 1 结束时还有未完成任务，督促消息进入 steer 队列，外循环再起 run 2。只有 agent_settled 表示真正停稳。
    哪个进程不加载 TillDone？
    subagent 子进程的命令是 pi --mode json --print --no-session …，里面没有 -e tilldone。所以子 agent 不受门禁和督促管。
