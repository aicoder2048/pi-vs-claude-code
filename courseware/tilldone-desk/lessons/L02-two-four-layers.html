L02 · 两套四层

两套四层叠在一起

边牧里有两套四层结构。一套在 Pi 扩展里，一套在桌面端。两套只在一个地方相接。这一课讲清每一层管什么，以及每个事实由谁说了算。

原文：§2、§2.1阅读约 15 分钟含 3 个互动演示

学完本课，你能够：

  • 说出四层架构每一层的职责和“不做什么”。
  • 把扩展（E-）和桌面（D-）的文件放进正确的层。
  • 指出两套四层唯一的接缝，并解释“格式只定义一次”。
  • 对任务清单、运行状态等事实，说出它的权威和到达界面的路径。

01四层是什么

先说结论：四层自下而上编号。下层不知道上层。每一层都有一条“不做什么”的边界。

定义来自讨论稿 discussions/2026-10-28-four-layer-harness.md。

层名称做什么不做什么
L1Pi 运行时搬运和累积上下文不判断内容好坏
L2ExtensionAPI 胶水在 L1 的固定插入点上挂回调不放业务规则
L3业务逻辑决定什么信息进上下文不碰渲染
L4界面独立的数据通道不占上下文
怎样记L1 搬运，L2 接线，L3 拿主意，L4 给人看。

02两套四层

边牧把这套分法用了两次。扩展一套，编号加前缀 E-。桌面一套，编号加前缀 D-。

层扩展（E-，在 Pi 子进程里）桌面（D-，在 Electron 里）
L1Pi 本身，不改外部 pi 子进程 + Electron 运行时
L2 胶水extensions/tilldone/index.ts：持有唯一的 model 单元，把 Pi 事件翻译成 L3 调用src/desk.ts、rpc.ts、jsonl.ts、main.ts、config.ts、credentials.ts：唯一持有可变状态
L3 领域extensions/tilldone/state.ts：零 import；模型能看到的所有字符串都定义在这里src/domain.ts、appearance.ts、api-domain.ts：纯函数 reduce(state, record)、planIntent、toViewModel
L4 渲染无。桌面副本删掉了 TUI 的 ui.ts 和 themeMap.tsrenderer/：只画 JSON 视图，只发意图

桌面 D-L2 的核心只有一行：this.state = reduce(this.state, record)（src/desk.ts:31）。所有 RPC 事件都走这一行。

D-L2 还会自己生成 desk_* 记录，例如时钟和进程退出。所以 D-L3 里没有 Date.now()，也没有 I/O。

补充：桌面副本为什么没有 E-L4仓库里 TUI 版扩展的 ui.ts 负责终端界面：widget、页脚、状态栏、工具卡片和 /tilldone 浮层。RPC 模式下没有终端界面，这些画法都没有用处。所以提交 01a9921 把它从桌面副本里删掉了，副本只剩 index.ts（L2）和 state.ts（L3）。themeMap.ts 也一起删了：RPC 拒绝 setTheme，窗口标题由桌面端自己设置。桌面端用 D-L4 画任务面板，数据全部来自工具结果里的 details。依据 apps/tilldone/README.md 和 index.ts 开头的注释。

04唯一的接缝

先说结论：两套结构之间只有一条依赖。D-L3 import E-L3 的四个选择器。所以任务数据的格式只定义一次。

  • parseDetails：把工具结果里的快照还原成清单。
  • countByStatus：按状态计数。
  • current：取第一个进行中的任务。
  • STATUS_ICON：三种状态的图标。

两边都能共用 E-L3，因为它零 import。state.ts 开头写明 “Zero imports by design”。测试 state.test.ts 强制检查这一点。

本节核心句桌面端从不调用 gate 或 runTool。规矩只在 Pi 进程里执行一次，桌面端只做投影。
补充：源码里实际 import 了几个原文列的是四个选择器。核对 src/domain.ts 第 6 行，它还 import 了 EMPTY_LIST、SPLIT_HINT_EVERY、TOOL 和类型 ListState。这些都是常量或类型，不是规矩的执行代码。所以“只投影、不执行”的结论不变。

05谁是权威

先说结论：每个事实只有一个权威。桌面端只读权威的投影，从不自己重算。

    07自测与速记

    两套四层之间唯一的依赖是哪一条？
    原文 §2：D-L3 import E-L3 的 parseDetails、countByStatus、current、STATUS_ICON。所以任务数据格式只定义一次。
    桌面端为什么不调用 gate 或 runTool？
    原文 §2：桌面端从不调用 gate 或 runTool。规矩只执行一次，桌面端只读结果。
    RPC 线上来了一份坏的 tilldone 快照，任务面板会怎样？
    parseDetails 逐字段校验，任何一处不对就返回 undefined。reduce 用 ?? state.list 保留旧清单。
    每个任务的工具次数由谁说了算？
    原文 §2.1：桌面 D-L3 从 tool_execution_start、turn_start 计数。它不进模型上下文，扩展的 spent 也不在线上。
