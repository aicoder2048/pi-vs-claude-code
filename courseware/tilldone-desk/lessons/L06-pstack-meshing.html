PStack 与 TillDone 的咬合

Poteto Mode 下，模型同时维护两份清单，并要穿过两道门。这一课逐步看它们怎样咬合，以及代码里真正相接的地方只有三处。

原文：§5–6阅读约 20 分钟含 3 个互动演示

学完本课，你能够：

  • 列出 PStack 在 Pi 里注册的命令、钩子和工具。
  • 说出两份清单各放什么，以及只有哪一份驱动面板、门禁和督促。
  • 按顺序讲出一次 Poteto 会话的 6 步咬合，指出每一步经过哪道门。
  • 用 requestedModels 的规则判断计费门会不会拦下一个 subagent 调用（计费门）。
  • 说出三个接缝，并解释为什么“大脑 / 手脚”之说只对一半。

01PStack 在 Pi 里注册了什么

先说结论：PStack 的 Pi 版本是 npm 包 pi-pstack。它在 Pi 里注册两个命令、三个事件钩子和四个工具。全部写在 pi-pstack/extensions/pstack/index.ts 一个文件里。

名称类型作用
/poteto-mode、/setup-pstack命令开关 Poteto Mode；交互配置角色 → 模型
input 钩子事件看到 /skill:poteto-mode 开头的输入，就开启 mode，并写 custom entry
before_agent_start 钩子事件mode 开启时，给每次请求追加 system prompt
tool_call 钩子事件对部署、递归删除等外部写操作的 bash 命令，要求确认
pstack_todo工具get/set/add/complete 一份字符串清单；写 custom entry pstack-todo
pstack_sessions工具列出当前工作目录的会话文件
pstack_config工具读写 models.json 的角色 → 模型映射
subagent工具单个 / 并行（有上限）/ 链式分派子 agent

poteto-mode/SKILL.md 对清单有两条要求，原文如下：

Start every multi-step task with `pstack_todo`; its first item is to read the Principles section below in full.SKILL.md
Your first `pstack_todo` actions are the matched playbook's steps, copied in verbatim, before any task-specific todos and before you reason about the task.SKILL.md

子 agent 的命令行（pstack/index.ts:145-148）：

pi --mode json --print --no-session --append-system-prompt <agent 提示文件>
   [--model <m>] [--tools <列表>] "Delegated task:\n<task>"
注意子进程不加载 TillDone。命令行里也没有 --no-extensions。L07 会讲这两点带来的坑。

边牧怎样开启 Poteto Mode：TILLDONE_PSTACK=1 时，桌面端把会话的第一条空闲 prompt 改写成 /skill:poteto-mode <你的话>（src/domain.ts:397-404）。pstack 的 input 钩子看到它，就开启 mode。之后的消息照原样发送。

为什么不用 /poteto-mode 命令原文说明：/poteto-mode 在 RPC 下会失败，报错 ctx.sendUserMessage is not a function。这是 pstack 的 bug。所以桌面端改用 /skill:poteto-mode。

02两份清单的分工

先说结论：Poteto Mode 下模型维护两份清单。tilldone 放工作项，pstack_todo 放流程步骤。只有 tilldone 有约束力。

维度TillDone（tilldone）PStack（pstack_todo + subagent）
清单里装什么工作项（羊）流程步骤（playbook 的步骤，逐字抄）
谁看得见任务面板、门禁、督促都靠它只有模型（和工具卡片）
约束力硬 bash/edit/write/subagent 必须有进行中的任务；没做完催一次软 只有提示词，没有门禁，没有督促
怎么“拆”split 把任务拆成更小的任务不拆任务；把一个任务分派给子 agent（并行或链式）
持久化工具结果里的 details 快照custom entry
改 system prompt从不每次请求追加一段

README 的原话：

In Poteto Mode the model keeps two lists: `pstack_todo` for pstack's process steps … and `tilldone` for the work items shown in the task panel. Only `tilldone` drives the panel, the gate, and the nudge.apps/tilldone/README.md
关键限制这条分工只写在 README 里。TillDone 的工具说明和 PStack 的 SKILL.md 都没有提到另一份清单。所以模型看不到它，要自己摸索。§5 和 L07 会展开。

04动手看：计费门

先说结论：计费门拒绝任何会落到 anthropic/* 的子 agent 调用。原因是用户的 Anthropic API 按量计费，没有充值。它在 state.ts:423 的 billingGate，先于门禁执行。

requestedModels 的规则：

  • subagent：检查顶层参数、tasks[] 和 chain[] 的每一项。
  • 某一项有显式 model，就只看这个 model。
  • 没有显式 model，就按 role 查 models.json。模型池里的每个模型都算。
  • pstack_config：只看 set 动作的 model 和 models。
游乐场：拼一个调用，看计费门怎样判
试三件事：给一项选 anthropic/… 的显式 model；只选 role “judgment and prose”；选 role “arena runners”，它的模型池里混着一个 anthropic 模型。判定逻辑照抄 state.ts 的 requestedModels 和 billingGate；拒绝文本照抄 BILLING_REASON。上方的 models.json 是演示用例子，不是用户的真实配置。
覆盖范围计费门只覆盖第一层。子 agent 不加载 TillDone，所以子 agent 再派的子 agent 不经过它。README 已经说明这一点。
补充：计费门比实际选模型更严pstack 真正启动子 agent 时，只从模型池里按序号取一个（childModel）。计费门却检查池里的全部模型。所以模型池里只要混着一个 anthropic/*，计费门就拒绝整次调用。这是课程作者读代码的观察，原文没有讨论。

05代码里只有三个接缝

先说结论：TillDone 和 PStack 在代码里只有三处结合。除此之外，两边互不认识。

  1. 反转的门禁（state.ts:377）：让 pstack 的工具能通过，只把 subagent 算作“会改东西”的工具。
  2. 计费门（state.ts:423，在 index.ts 的 tool_call 里先于门禁执行）：检查 subagent 和 pstack_config set 的模型。
  3. 子 agent 进度显示（src/domain.ts:503 的 parseChild）：桌面 D-L3 解析 subagent 的 partial result，显示子 agent 实时树。只给界面。

原文的证据是 grep：state.ts 只在计费部分提到 pstack；pi-pstack 的 SKILL.md 完全没有提到 tilldone。

06“大脑 / 手脚”只对一半

讨论稿给过一个分工说法：

Tilldone 是大脑：管任务拆解和分工。PStack 是手脚：管任务的落实和执行。discussions/2026-11-01-traing-agent-tilldone-pstack-claudetraingskills.md

原文按代码检查后认为，这个说法只对一半。

TillDone 不是“大脑”

它自己不拆任务。它是账本 + 闸门 + 督促。拆的决定由模型在它给的时机上做出（见 L05）。

PStack 不只是“手脚”

它带着自己的计划清单（playbook 步骤）。它还有另一种“拆”：把工作分派给子 agent。

原文的结论TillDone 管“做什么、做完没”，用硬约束守住。PStack 管“怎么做”，只靠提示词引导。

原文还给了一个判断：“两份清单各管什么”只写在 README 一行里，模型看不到。所以现在的“有机结合”是模型每次自己摸索出来的，不是设计保证的。

限定语这是推断。依据是 §6.3 的 grep 结果，没有对模型行为做实验。

07自测与速记

Poteto Mode 下，哪份清单驱动任务面板、门禁和督促？
README：“Only `tilldone` drives the panel, the gate, and the nudge.” pstack_todo 只有提示词约束。
在 TUI 原版门禁下，Poteto 会话开头的 pstack_todo set 会怎样？
原版不认识别的扩展加的工具。Blackjack 运行里，原版门禁拦了 pstack_todo 5 次。桌面副本把门禁反转成只拦 bash/edit/write/subagent（提交 7437421）。
一次并行 subagent 调用：task A 显式 model 是 openai-codex/gpt-6.1-sol，role 是 “judgment and prose”（映射到 anthropic/…）；task B 没有 model，role 是 “swarm workers”（inherit-parent）。计费门怎样判？
requestedModels：某一项有显式 model 就只看它。A 只算 openai-codex；B 的 inherit-parent 不匹配 anthropic/。所以放行。
