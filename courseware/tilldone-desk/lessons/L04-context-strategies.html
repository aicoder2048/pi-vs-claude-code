L04 · 上下文管理

两种注入策略与抗压缩

TillDone 和 PStack 都要把话说给模型听，但走的路不同。这一课比较两条路，再看 subagent 怎样隔离上下文，以及状态怎样扛住压缩。

原文：§3.3、§3.5阅读约 18 分钟含 3 个互动演示

学完本课，你能够：

  • 说出 TillDone 用哪三条通道把规矩送进上下文，以及为什么它不改 system prompt。
  • 说出 PStack 的两处注入：system prompt 注入和首条消息里展开的 SKILL.md。
  • 解释 subagent 怎样做到上下文隔离，以及它的代价。
  • 说出清单、pstack_todo、Poteto 开关各从哪里恢复，哪些状态不持久化。

01两种策略，一句话

先说结论。两个扩展选了相反的注入策略。

TillDone

从不改 system prompt。规矩全部通过“工具说明 + 工具结果 + 自定义消息”送进去。

PStack

每次请求都改 system prompt。它还在首条消息里展开整份技能。

TillDone 从不改 system prompt。规矩全部通过“工具说明 + 工具结果 + 自定义消息”送进去。所以它对 Pi 升级和别的扩展改 system prompt 都不敏感。§3.3

两条路各有用处。TillDone 的规矩只在触发它的时刻出现。PStack 的工作方式要贯穿整个会话，所以它占据每次请求的开头。

02TillDone：不碰 system prompt

TillDone 没有挂 before_agent_start。它只用 Pi 本来就会送给模型的三种东西。

三条通道都不经过 system prompt。依据原文 §3.1 与 §3.3 重画。

这样做有两个好处。

  • 规矩跟着工具走。只要 tilldone 工具还注册着，工具说明就在每次请求里。
  • 别人改 system prompt 碰不到它。Pi 升级换默认提示词，或者别的扩展改写提示词，TillDone 的规矩都照样到达。

03PStack：每次追加一段

PStack 有两处注入。一处每次都在，一处只发生一次。

  1. system prompt 追加。Poteto Mode 开启后，before_agent_start 钩子在每次请求的 system prompt 末尾加一段说明（pstack/index.ts:272-276）。
  2. 首条消息展开技能。首条消息是 /skill:poteto-mode …。Pi 把整份 poteto-mode/SKILL.md 展开进这条消息。之后它留在历史里，不再重复发送。
Pstack Poteto Mode is enabled for this session. Follow its persisted workflow: use pstack_todo for non-trivial work, select and read the matching playbook, delegate through the subagent tool when delegation helps, verify real behavior, and name only principles that changed a decision. The full skill is at <pi-pstack>/skills/poteto-mode/SKILL.md.§3.1，pstack/index.ts:272-276

源码里，这段说明后面还跟着 SKILL.md 的完整路径。模型忘了细节时，可以用 read 重读技能文件。

补充：追加，而不是替换源码写的是 `${event.systemPrompt}\n\n…`。它在已有提示词后面追加，不会丢掉 Pi 的默认提示词。这一点读源码可以确认。

05subagent：上下文隔离

先说结论：subagent 让子 agent 在自己的进程里干活，父上下文只收到结论。原文把它归为 Delegation。

subagent 本身是上下文隔离：子进程带 --no-session，完整过程留在子进程里，父上下文只拿结论。这是 Delegation。§3.3

源码里有四个细节决定了父上下文收到多少。

  • 工具结果的 content 只放结论文本。子 agent 的完整消息放在 details.results 里，见 content 与 details。details 不进模型上下文。
  • 并行模式下，每个子 agent 的结果截断到 50 KB（MAX_MODEL_OUTPUT_BYTES = 50 * 1024）。单个模式和链式模式不截断。
  • 链式模式只把最后一步的结论送回父上下文。前一步的结论经 {previous} 写进下一步的任务，只有子进程看得到（pstack/index.ts:410-419）。
  • 并行模式最多 8 个任务（MAX_PARALLEL_TASKS = 8），同时最多跑 4 个（MAX_CONCURRENCY = 4）。

桌面端的子 agent 实时树读的就是 details.results。所以你在界面上看到的过程，模型看不到。

06动手看：父上下文涨多少

同一批工作，可以自己内联做，也可以分派给 subagent。拖动滑块，比较父上下文的增长和总花费。

模拟：内联做 vs 分派 subagent，父上下文的增长
把“每个工具结果”往大拖。内联做时父上下文跟着线性涨，分派时父上下文几乎不动。再看“分派：总新增 token”一行：分派并不省总 token。每个子进程有自己的上下文和固定开销。隔离买到的是父上下文的干净，不是更低的总成本。
简化模型，数字是假设，不是原文结论。假设：每次工具调用的参数 80 token；分派时每个子任务的任务说明 200 token；每个子进程固定开销 3000 token（system prompt 与 agent 提示）；50 KB 截断按约 12,800 token 计。只计入新增上下文，不计模型的累计重复读取。
代价子 agent 内部做了什么，父 agent 只能从结论里知道。TillDone 也看不见它：一次 subagent 调用在 spent 里只算 1 次。L05 和 L07 会讲这个盲区。

07抗压缩：状态不放在对话里

先说结论：两个扩展都不依赖对话记忆。压缩只改模型看到的历史，碰不到扩展内存和会话文件。

两者都把状态放在会话文件里，不依赖对话记忆。§3.5
状态运行中的权威重启后从哪恢复切换会话分支后
TillDone 清单扩展内存 model.list会话分支里最后一个有效的 tilldone details（state.ts:180 restore，经 parseDetails 校验）从新分支重建
pstack_todo 清单扩展内存 todoscustom entry pstack-todo（pstack/index.ts:250-262）不变，仍是切换前的清单
Poteto 开关扩展内存 potetoModecustom entry pstack-mode不变
spent、nudged扩展内存不持久化，重启后归零spent 清零；nudged 保留

TillDone 在 session_start 和 session_tree 时恢复。parseDetails（state.ts:167）把读到的快照当不可信数据，逐字段校验。

切换分支时两边不同步在会话树里切到另一个分支时，Pi 发出 session_tree。TillDone 监听它，从新分支重建清单（restore 让 spent 归零、保留 nudged）。PStack 只在 session_start 时读取 custom entry，不监听 session_tree，所以 todos 和 Poteto 开关仍是切换前的值，可能和新分支对不上。依据：原文 §3.5（2026-11-04 读源码补）、index.ts 和 pstack/index.ts:250。
逐步看：压缩与重启时，三处状态各变成什么
先点“压缩”：模型上下文里的早期消息变成摘要，扩展内存和会话文件不变。再点“重启并恢复会话”：内存从会话文件重建，spent 和 nudged 归零。
简化模型：会话内容是演示用例子。“压缩后 SKILL.md 全文可能变成摘要”是推断，没有实际运行验证。
补充：压缩后怎样拿回全貌清单的权威在扩展内存里。压缩后，模型调一次 tilldone list 或 pstack_todo get，就能拿回完整清单。这一条来自白皮书 8.4 节对 TillDone 的描述；PStack 部分按源码推断。

08自测与速记

TillDone 不用下面哪条通道把规矩送给模型？
原文 §3.3：TillDone 从不改 system prompt。它只用工具说明、工具结果和自定义消息。
PStack 的 Poteto Mode 说明多久注入一次？
before_agent_start 在每次请求时追加这段说明。首条消息里展开的是另一样东西：整份 SKILL.md，只发一次。
subagent 跑完后，父 agent 的上下文里有什么？
结论放在工具结果的 content 里。完整消息放在 details.results 里，只给界面和会话文件，不进模型上下文。
重启并恢复会话后，下面哪个状态会归零？
spent 和 nudged 不持久化。清单从 details 快照恢复，pstack_todo 和 Poteto 开关从 custom entry 恢复。

速记表

要点一句话
TillDone 策略不碰 system prompt；工具说明 + 工具结果 + 自定义消息
PStack 策略每次请求追加 system prompt；首条消息展开 SKILL.md
subagent 隔离--no-session 子进程；content 只放结论；并行 ≤ 8、并发 4、单个 ≤ 50 KB
隔离的代价不省总 token；父 agent 和 TillDone 看不见子 agent 内部
抗压缩清单 ← details 快照；pstack_todo、Poteto ← custom entry；spent、nudged 不持久化
