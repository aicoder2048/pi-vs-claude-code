L07 · 拆分与分工

坑、开放问题与全课复盘

前六课讲了边牧怎样工作。这一课讲它在哪里会出问题：哪些工作逃过了 TillDone 的约束，哪些分工没有写进提示词。最后把全课串成一张图。

原文：§7–8阅读约 20 分钟含 2 个互动演示

学完本课，你能够：

  • 说出原文列出的六条坑，以及每条的后果。
  • 解释为什么分派给子 agent 的工作不会触发拆分提示。
  • 区分原文的事实、推断和尚未做的建议。
  • 按四层、上下文、拆分与分工三条线复述全课。

01六条坑一览

先说结论：六条坑分成两类。前四条是约束的漏洞：有些工作或步骤不在 TillDone 的视野里。后两条是文档和文本的问题。

#坑性质
1子 agent 不受 TillDone 管事实（命令行可证）
2子进程很可能加载全局扩展；计费门只覆盖第一层前半是推断，没有实际运行验证；后半 README 已说明
3督促不管 PStack 的流程步骤事实（agentEnd 只看 tilldone 清单）
4两份清单可能重复或错位风险；最小修正尚未做
5白皮书过时事实；用户决定等设计固定再更新
6细分请求的语言随界面变化事实（白皮书 8.5 / R6 已记录）

02动手看：坑的走查

下面是一次模拟的 Poteto 会话。选一条坑，调参数，看后果出现在哪里。每条都给出原文定位和最小修正。

走查：四个约束漏洞
选一条坑：
先看 ①：把“子 agent 内部工具调用”拉到 40。然后对比“自己做”和“分派给子 agent”两栏。再看 ③：只取消“验证”那一项的勾，看督促是否发生。简化模型：spent 规则照 state.ts 的 toolCalled（每个非 tilldone 调用 +1，每满 15 提示一次）；督促规则照 agentEnd。任务和步骤文本是演示用例子。② 的“大概会加载”是原文推断，没有实际运行验证。
补充：坑 3 在界面上也看不出来任务面板、督促统计和“等你发话”的交还提示都只看 tilldone 清单。pstack_todo 只出现在它的工具卡片里，而工具卡片默认折叠。所以“验证”没勾时，用户看到的是全部完成的面板。依据原文 §7 第 3 条（2026-11-04 补）和 README。

03子 agent 的边界

先说结论：TillDone 的约束只到父进程为止。子 agent 是 TillDone 的盲区。

  • 子进程命令是 pi --mode json --print --no-session …，里面没有 -e tilldone。
  • 一次 subagent 调用在 spent 里只算 1 次。子 agent 内部做了多少工作，15 次提示和面板计数都看不到。
  • 所以分派出去的大任务看起来很“便宜”，不会触发拆分提示。
推断，未验证子命令行里也没有 --no-extensions。原文推断：~/.pi/agent/extensions 里的扩展大概会进子 agent。主子进程用 --no-extensions 挡住它们，子 agent 却没有这道挡板。

计费门也有同样的边界。它只检查父进程发出的 subagent 调用。子 agent 再派的子 agent 不经过它。README 原话：

Subagents spawned by subagents do not load this extension, so the rule covers the first level only.apps/tilldone/README.md
补充：为什么这条坑值得注意L05 讲过，15 次提示用来发现太粗的任务。分派给子 agent 恰好是处理大任务的常见做法。所以最需要提醒的任务，反而最难触发提醒。这是课程作者的推论，原文没有这样表述。

04开放问题

原文留下三个没有解决的问题。

问题 1 · 分工
两份清单怎样告诉模型

原文建议的最小修正：在 TOOL.description 里加一句，说明 tilldone 只放工作项，流程步骤放 pstack_todo。这一步需要改代码，尚未做。

问题 2 · 文档
白皮书过时

白皮书 v1.0（2026-10-31）的 0.1 节和第 3 章仍写“桌面端只加载 tilldone”。pstack、反转门禁、计费门、子 agent 树都没写。用户决定等设计固定后再更新，避免白做。

问题 3 · 文本
细分请求的语言

splitRequest 按界面语言取中文或英文。它是一段模型可见的文本。所以界面设置会影响模型的输入。

读课程时的提醒本课程初版按提交 f112eb9 编写，2026-11-04 对照提交 8c2f42e更新了行号和内容。边牧还在变化。遇到和代码不一致的地方，以源码为准。

07自测与速记

模型把一个大任务分派给子 agent，子 agent 内部用了 40 次工具调用。父进程里这个任务的 spent 增加多少？
一次 subagent 调用在 spent 里只算 1 次。子进程不加载 TillDone，内部调用看不到。所以不会触发 15 次拆分提示。
tilldone 清单全部完成，但 pstack_todo 里“验证真实行为”没勾。run 结束时会怎样？
agentEnd 只看 tilldone 清单。PStack 的流程步骤没有督促，也没有门禁。
“子 agent 大概会加载全局扩展”这条，原文给的是什么性质的结论？
原文 §7 第 2 条明确标为推断。依据是 pstack/index.ts:145 的子进程命令行。
