# 讲稿生成规范（给写讲稿的人和 AI 看）

AI 讲师照着**讲稿**讲一课：滚动到正在讲的地方并高亮，操作演示，用语音讲解，遇到常见疑问就公开问 AI 助教。
讲稿由 Claude 在 Claude Code 里离线写好，存进仓库；上课时不让模型现场决定讲什么。这样质量稳定、没有延迟，按量计费的模型只在学生触发时才调用。
学生不审讲稿，所以质量全靠这份规范和 `check` 命令来保证。

## 名词

| 名词 | 含义 |
|---|---|
| 讲师 | 主讲的 AI。掌控节奏，翻页、高亮、操作演示、语音讲解。重点话题由它亲自讲 |
| 助教 | 页面右栏的 AI。只回答提问，从不主动推进课程 |
| 讲稿 | 讲师讲一课时依次执行的步骤，存为 `scripts/<课号>.json` |
| 重点话题 | 一课里讲师着重讲的核心内容：心智模型、关键概念、设计框架。每课 2–4 个 |
| 代问 | 讲师替学生向助教公开提一个常见疑问，助教的回答会被朗读。每课 1–2 次 |
| 换个讲法 | 学生按 `R`，讲师当场把当前这一步换个角度重讲（现场调用模型） |

课号就是讲稿的文件名，和课程页文件名的前缀一致：`L02-xxx.html` 的讲稿是 `scripts/L02.json`。

## 写一课讲稿的流程

1. 通读这一课的页面和它对应的原文章节。
2. 挑 2–4 个重点话题，每个小节最多 1 个。
3. 按小节顺序写步骤，存为 `scripts/<课号>.json`。
4. 自检，直到 0 个错误，提醒逐条看过：
   ```bash
   cd <课程目录>/lecturer && uv run lecturer.py check <课号> --readouts
   ```
   `check` 直接打开本地页面文件，不需要启动课程服务，也不调用任何模型。`--readouts` 打印每个演示步骤操作后的页面读数：**讲稿里说的每个数字都要和它对上**。
5. 预合成音频：`uv run lecturer.py audio <课号>`（edge-tts，免费，需联网，每课约 1 分钟）。
6. 听一遍：`python3 tools/course.py --lecture <课号>`。

## 文件格式

```json
{
  "lesson": "L02-two-layer.html",
  "title": "双层架构：Router 与 Worker",
  "steps": [ { "id": "s1-01", "section": "s1", "kind": "say", "target": "#s1 h2", "say": "……" } ]
}
```

每一步都有这些字段：

| 字段 | 含义 |
|---|---|
| `id` | 唯一，写成 `小节-序号`，如 `s3-02` |
| `section` | 所在小节的 id（`s1`…）。`--from s3` 靠它定位。开场白用 `s0` |
| `kind` | `say`、`demo`、`proxy`、`quiz` 四种之一 |
| `target` | CSS 选择器。讲这一步时，页面滚到它并画出高亮框 |
| `nth` | 可选。`target` 匹配到多个元素时取第几个（从 0 开始） |
| `say` | 讲师说的话 |

不同 `kind` 还需要额外字段：

- **say**：普通讲解，没有额外字段。
- **demo**：讲师操作演示。需要 `actions`，它们在讲师开口**之前**依次执行，所以 `say` 描述的是操作后的结果（“我把间隔拖到半分钟，你看……”）。可用的 action：
  - `{"set": "#d1-g", "value": "0.5"}`：设置滑块、下拉框或输入框的值，并触发 `input`/`change` 事件。
  - `{"set": "#d1-fix", "value": "true"}`：勾选复选框（`"false"` 取消勾选）。
  - `{"click": "#d2-next"}`：点击按钮。
  - `{"wait": 600}`：等待若干毫秒，让动画或重绘完成。
- **proxy**：代问。`say` 是讲师引出问题的话；`question` 是讲师在右栏公开发给助教的问题。
- **quiz**：自测题。`target` 指向 `.quiz`，用 `nth` 选第几题。讲师用 `say` 读题和选项，然后自动暂停等学生作答；学生按空格后，没作答的话讲师替他点出正确答案，再讲 `explain`。

## 写作要求

**写的是说的话。** 讲稿会被语音合成原样读出来。
- 口语化，短句，一句不超过 30 字。不要照念页面原文，要像老师站在屏幕旁边讲。
- 每一步的 `say` 和 `explain` 写 40–150 字。超过 150 字就拆成两步（`check` 会报错）。
- 不要念表格、代码、公式。讲“这张表说明了什么”。
- 英文术语照常说，数字写成读得出来的形式（“2.5 秒”可以，TTS 能读）。
- 缩写和代码的读法交给读音表 `lecturer/pronounce.json`，讲稿里照常写 EMA、SPY。edge-tts 会把 SPY 读成单词：表里写成 `"SPY": "S P Y"`、`"EMA": "E M A"`（空格隔开；不要用顿号，会一字一顿）。MA 交给 edge-tts 自己读，不放进表。人名写成中文读法（`"Ming Xu": "胥明"`）。股票代码读公司名（`"NVDA": "英伟达"`），会被误读的缩写读全称（`"IV": "隐含波动率"`）。讲稿里出现表里没有的缩写时，先补进表再合成。
- 不用 Markdown、括号注释、表情符号：它们会被读出来，或者读得很怪。代码名里的下划线也算（`check` 会提醒）：写成口语形式，如 agent_settled 写“agent settled”。
- 课程里有可能造成危害的原文示例（如一条注入命令）时，概括着讲，不要把命令本身读出来。

**开头和结尾。**
- 开头两步放在 `s0`：`.hero` 上的开场白（上一课讲了什么、这一课的一句话预告），`.objectives` 上的学习目标。
- 结尾两步：速记表上的全课收束（一条主线串起重点话题）；“相关课程”上预告下一课。最后一课改成全课程总结。

**重点话题由讲师亲自讲。**
- 先给结论，再给一个比方或场景，最后点出它和前后内容的联系。
- 一个重点话题可以连续占两三步，配合高亮对应的段落、图或演示。

**代问只做补充。**
- 问讲师**讲过之后**学生仍然自然会冒出来的疑问：边界条件、反例、和熟悉系统的类比。不要让助教替讲师讲重点。
- `question` 要带约束：“请用 3 句话、120 字以内回答，先给结论，不要列表和表格。”。只写“200 字以内”压不住：实测助教答了 421 字，朗读 85 秒。
- 助教把“正在看的小节”当上下文，所以代问步骤的 `target` 指向相关小节。
- 不要重复右栏的快捷问题按钮。

**演示要动手。**
- 每个演示都要操作，并展示两种对比状态（“先看间隔大时……再拖小……”）。
- 操作前说看哪里，操作后说看到了什么、说明了什么。
- **每个 demo 步骤自己把演示带到确定状态。** 学生可以按 ← 回放任何一步，所以这一步不能依赖前一步留下的状态。做法：复选框一律用 `set`，不用 `click`（click 是切换，回放时会反过来）；会累积状态的演示，先点它的“重置”再操作。`check` 会把每个 demo 步骤连做两遍，结果不一样就报错。
- 讲稿里的数字必须是页面上真能看到的数字。用 `check --readouts` 核对，不要凭记忆或心算。

**自测题。**
- `say` 读题干和全部选项，每个选项前说出字母（“A，……。B，……”），最后提醒“选完按空格”。
- 题目问“哪一项不符合”时，读题时强调出来。
- `explain` 说出正确选项的字母和理由，再点一句最迷惑人的错项错在哪。

**区分原文和补充。** 页面上标为“补充”的内容是课程作者的解释。讲到它们时说“课程这里补充了一个比方”，不要说成原文的观点。原文的限定语（“初步”“原型”“在他们的规模下”）要保留。

## 写讲稿时顺手做的事

写讲稿要逐句对照页面和原文，是一次很好的复核。发现课程页面本身的问题（数字方向写反、前后矛盾、选择器失效）时，不要在讲稿里悄悄绕开，写进交付报告，由课程作者决定怎么改页面。

## 示例

```json
{ "id": "s1-04", "section": "s1", "kind": "demo", "target": "#demo1",
  "actions": [{ "set": "#d1-g", "value": "0.5" }, { "wait": 700 }],
  "say": "我把事件间隔拖到半分钟，让事件变得很密。看第一行，单 Session 全部做完还是 48 分钟，一分钟都没少。" },
{ "id": "s3-05", "section": "s3", "kind": "proxy", "target": "#s3",
  "say": "讲到这儿，用过 Claude Code 的同学可能会问：主会话加 Subagent，算不算双层架构？我们请助教来说说。",
  "question": "Claude Code 的主会话加 Subagent，算不算本课说的双层架构？请用 3 句话、120 字以内回答，先给结论，不要列表和表格。" },
{ "id": "s6-02", "section": "s6", "kind": "quiz", "target": "#s6 .quiz", "nth": 1,
  "say": "第二题，注意是选不符合原文的。关于 Router 层：A，它是序点、协调点和记忆。B，它可以不配 Bash。C，它通常需要最强的模型。D，它只负责交互和分派。选完按空格。",
  "explain": "答案是 C。需要最强模型的是 Worker，因为它直接决定交付质量。Router 只做轻量的交互和分派，轻量模型往往就够了。" }
```
