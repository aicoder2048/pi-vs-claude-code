弈境全景：让 LLM 真的落子

弈境是一个人机五子棋桌面应用。机器棋手是一个 LLM，它必须调用工具才能落子。这一课建立全景：为什么这样设计，四层各管什么，一手棋怎样从点击走到落子。

原文：白皮书 §1–2.4 + 代码现状勘误阅读约 15 分钟含 2 个互动演示

学完本课，你能够：

  • 说出弈境要同时满足的四条约束。
  • 说出四层架构每层拥有什么权威、不许做什么。
  • 区分运行时调用链和编译依赖方向。
  • 按顺序讲出一手棋的往返，并指出落子在哪一步真正发生。
  • 说出白皮书 v1.0 之后代码的三项主要变化。

01为什么不用搜索 AI

先说结论：弈境不是为了做出最强的五子棋程序。它要回答一个工程问题。

如何让一个通用 LLM 在一个有硬规则、有时限、有对抗的领域里做出可审计的决策，并且让它的每一步都受到工程约束？白皮书 §1.1

做五子棋程序，最省事的做法是 α-β 搜索，再把结果包装成“AI 说”。弈境刻意不这样做。它要同时满足四条约束：

约束 1
规则不可协商

合法性、胜负、棋钟、轮次只由代码裁决。任何自然语言都改写不了。

约束 2
LLM 必须真的做决定

应用不替模型下棋。应用也不从模型的文字里抠坐标直接落子。

约束 3
过程可审计

能看到模型基于什么证据做决定。但不索取私有思维链。

约束 4
时间是真实资源

网络等待、工具调用、重试都扣棋钟。

本课程的核心句权威留在宿主，模型通过端口提交。规则在代码里，事实在信号里，经验在 Markdown 里。

03四层全景

弈境自下而上分四层。编号与仓库里的边牧（TillDone Desk）一致。

层主要文件拥有的权威不许做的事
L1 Agent Loopsrc/agent/pi-driver.ts 等本回合 Pi Session 的生命周期：模型解析、请求预算 8、技术超时 90 秒、取消、工具白名单校验不判断落子是否合法，不碰棋钟
L2 Pi 扩展src/extensions/gomoku.ts本回合的工具面：8 个工具、调用预算 16、证据门禁、提交前反馈、决策证据组装不直接改棋谱，提交只走 port.commit
L3 业务src/business/**棋谱、revision、轮次、棋钟、比分、胜负，以及唯一写入入口不 import Pi 或 Electron
L4 桌面src/electron/*、src/renderer/*进程组合、200 ms 心跳、IPC 校验、原子保存、可视化渲染器不能提交 LLM 落子，不能改权威棋谱

注意两个方向。运行时调用链自上而下：点击 → 业务 → Agent → 扩展。编译依赖却指向中心的 L3：L1、L2、L4 都 import L3，L3 一个都不 import。这就是端口与适配器。

04一手棋的往返

先说结论：一手棋 = 一个新的内存 Session = 一次 session.prompt() = 一次 settle。落子只在 L2 调用 port.commit() 时发生，由 L3 校验后写入。

“人类落子 → LLM 应手”按这个顺序走：

  1. 渲染器发 five:command { move, x, y, revision }。主进程校验发送方和命令形状。
  2. GameService.humanMove() 先结算棋钟，再校验 revision，然后落子、重放、分析。
  3. startAgent() 新建 AbortController 和本回合的 TurnPort。状态变成“思考中”并推送给界面。
  4. L3 调 driver.run(port)，不 await。L1 用 turnGuidance() 选剧本，装配系统提示词。
  5. L1 创建内存 Session。Pi 在 reload() 中执行扩展工厂，注册 8 个工具。
  6. L1 调 session.prompt(棋谱 + 棋盘 + 信号 JSON)。run 内循环开始：模型回复，Pi 顺序执行工具。
  7. 模型调 place_stone。L2 检查证据，调 port.commit(point, reason, trace)。L3 结算棋钟、校验 valid()、落子、切换棋钟。
  8. L1 看到提交成功，立即 abort()。Session 停稳后 dispose()。界面收到新快照并自动保存。
常见误解“模型在回复里写出坐标，应用就落子。”不对。模型的文字从不作为落子来源。没有成功的 place_stone 工具调用，棋盘就不变。

    07自测与速记

    模型在回复文字里写了“我下 H8”，但没有调用工具。棋盘会怎样？
    约束 2：应用不替模型下棋，也不从自然语言里抠坐标。落子只在 port.commit() 成功时发生。
    下面哪一层不 import 任何其他层？
    编译依赖指向中心的 L3。L3 只定义 TurnPort 和 AgentDriver，不 import Pi 或 Electron。
    模型思考时，人类悔棋。之后模型调用 place_stone。结果是什么？
    悔棋让 revision++ 并中止当前回合。L2 的 ensureActive() 抛错；即使提交到了 L3，valid() 也会因 revision 不符而拒绝。
    按代码现状，弈境注册了几个领域工具？
    白皮书 v1.0 写的是 6 个。v2 加了 check_forcing_sequences，v3 加了 find_forcing_win，现在是 8 个（gomoku.ts:11）。16 是工具调用预算，15 是知识条目数。
