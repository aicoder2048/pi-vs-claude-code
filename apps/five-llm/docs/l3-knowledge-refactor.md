# L3 知识与决策信号重构

> 本文记录 v1 重构及其当时的验证结果。后续 v2 已增加第七个工具、连续先手反证技能、提交前反馈与候选级证据；当前契约见 [连续先手检查](forcing-review.md)。

## 目标与边界

参考仓库 `discussions/2026-10-30-pstack-analysis-grok.md` 与 `2026-10-30-refactor-five-llm-pstack-grok.md` 的分析，借鉴「原则索引 → 编排 → 剧本 → 技能 → 工具证据 → 验证」模式；不依赖或复制未经核验的 pstack 实现。

本应用是 **15 路自由五子棋**，不是 Renju。双三、双四、长连均不构成禁手；连续五子及以上获胜。`RULES.md` 保留为人类可读的比赛约定，不以提示词取代权威规则。

## 实施清单

1. 分离 `rules.ts`（确定性合法性、重放、胜负）与 `tactics.ts`（启发式棋形、候选排名），保留 `engine.ts` 兼容出口。
2. 建立应用自带知识包：编排入口、简短原则索引、开局/中盘/战术收束/时间紧迫剧本，以及威胁评估、合法性、提交前验证技能。每项写明触发条件、步骤、证据与局限。
3. 用纯函数生成结构化信号，区分全盘扫描的即时事实、局部候选启发式和棋钟建议。确定性路由优先级：终局退出；时间紧迫；立即获胜/必须应对的威胁；开局；中盘。时间剧本不能覆盖战术优先级。
4. Pi 只注入入口、原则索引和选中的剧本；通过白名单 `read_knowledge` 按需读取其他条目。不启用通用文件读取、编码工具、用户技能或扩展。构建复制知识资源，路径不依赖工作目录。
5. 保留三个原工具，增加 `evaluate_threats`、`validate_move`、`read_knowledge`。落子前要求本回合已获取分析证据，再做确定性候选验证；战略警告不拒绝合法棋步。最终的计时、回合、revision、一次性提交仍归 GameService。
6. 在成功落子的手记中追加可选的版本化决策证据：剧本、工具完成步骤、未试算的跳过原因与候选警告。沿用既有原子棋谱保存链路，不新建第二个可写状态源。
7. 测试规则兼容、信号/路由、知识包完整性、真实 Pi SSE 工具循环与门禁、记录隔离、取消/超时，并运行 typecheck、build、Electron smoke。

## 验收标准

- 原有自由五子棋规则、计时、多局比赛与桌面交互不回归。
- 立即获胜优先于防守；多处对手成五点不能误称「堵任一点就安全」。
- 分数、双三/双四标签不等于必胜证明，不把试算的单条变化当作穷举证明。
- 非法/过期/超时落子仍拒绝；低分但合法的棋步不被策略层强行替换。
- 只有选中剧本全文默认进入上下文；白名单读取不能越界读磁盘。
- 成功提交后不再向模型请求验证；所有验证在提交前执行。
- 棋谱可看出实际使用了什么证据，不保存或索取私有思维链。

## 实现位置与迁移

| pstack 借鉴点 | 本应用实现 | 不照搬的部分 |
|---|---|---|
| 入口/原则索引 | `knowledge/SKILL.md` + `decision.ts` 白名单索引；5 个独立原则技能 | 不默认加载所有全文 |
| 剧本路由 | `turnGuidance()` 选择 4 个剧本之一，步骤固定为 observe/compare/verify/commit | 不把 GameService 状态机转成自然语言 |
| 技能/执行器分离 | 3 项技能通过受限工具取得事实与验证 | 不把计算代码写成 Markdown |
| 共享进度 artifact | `DecisionTrace` 随 `TurnNote` 经现有棋谱原子保存 | 不增加第二套状态 JSON 单写者 |
| prove it works | `validateCandidate()` 在提交前扫描对手一步反击 | 不在提交后发起额外模型调用 |
| 独立审查 | 只读确定性候选验证 | 暂不启动额外 LLM subagent |

代码：`rules.ts` 管硬规则，`tactics.ts` 管启发式，`engine.ts` 作为兼容出口；`decision.ts` 管信号、路由、证据类型，均不依赖 Pi/Electron/I/O。`src/agent/knowledge-loader.ts` 单独承担受限资源读取，`src/extensions/gomoku.ts` 提供六个领域工具，`PiDriver` 显式注入知识上下文。

- 现有 `engine.ts` 导入无需迁移；`RULES.md` 保留并链接领域知识说明。
- 原三个工具保持名称与参数兼容，但 `place_stone` 现在要求先成功调用本回合的 analyze_position 或 evaluate_threats。非法请求可在原预算内修正。
- `validate_move` 是可选显式验证；`place_stone` 始终重复验证最终提交的候选，避免换点后沿用旧验证。
- 剧本在回合启动时选定并注入。evaluate_threats 会重新投影时间并提供最新路由建议；证据中的 playbook 记录启动时实际注入的剧本，而非假装动态加载了新全文。
- 记录格式仍为 `five-llm/v1`，仅新增可选的 `notes[].decision`，内部版本为 `gomoku-knowledge/v1`。旧棋谱/测试替身可不提供该字段；不引入历史棋谱导入功能。
- 决策记录只描述已成功取得的工具证据。compare 的 done 表示成功做过变化试算，不表示已穷举，也不推断模型是否在内部比较了候选；没有试算则明确 skipped。
- 默认注入入口、原则/知识索引和选中剧本；知识条目用内置 ID 读取。缺失资源导致本回合显式失败，不悄悄退回旧提示词，比赛棋钟仍继续。
- 知识资源随 build 复制到 `dist/business/knowledge/`。改动 Markdown 后重建并重启，无须修改 Pi 全局设置。新增条目必须同时更新白名单与完整性测试；改变信号/证据语义时应升级知识版本。

## 验证结果

- 基线：55 项测试通过。
- 实现后：`bun run check` 通过（TypeScript、**74 项测试**、构建）；新增 19 项测试覆盖知识资源、白名单、按需注入、路由/时间投影、一步事实与权威落子逐点比对、提交门禁、记录隔离与真实 Pi SSE 工具循环。
- `bun run test:smoke` 通过：真实 Electron 下棋、回看、练习悔棋、棋钟/赛制、超时、自动保存及既有音频/窗口布局无回归。smoke 使用显式测试替身，不冒充真实 LLM 棋力评测。
- 构建后的知识加载器在无关 `/tmp` 工作目录下由 Node 成功读取剧本与技能；13 项打包资源均与源码一致。
- 回归测试发现混合工具批次只靠 `terminate: true` 不一定结束整个 Agent Loop；现已在成功提交事件停止同批后续工具和下一次模型请求，测试验证只提交一次、只请求一次响应。
- 没有访问真实外部模型或使用用户 API 额度；尚未验证模型对知识的实际遵循率，也未证明棋力提升。

## 暂缓项

- 多模型 review-agent / 并行 simulate-agent：先用确定性反击扫描实现低延迟只读审查。新增模型请求的费用、用时预算、故障传播与收益需独立评测后再引入。
- `.five-llm/state` 和模型角色配置：已有 GameService 单写者与棋谱原子保存，暂不复制状态；只有出现跨会话编排需求才引入。
- Renju 禁手识别：属于新规则集，必须独立设计与测试，不可作为此次自由五子棋重构的附带变更。
- 棋力提升声明：此次验证架构与证据正确性，不声称比原版赢棋更多；真实模型对弈评测需另行建立。
