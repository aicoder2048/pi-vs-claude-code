# 弈境 · Five LLM

经典木质棋盘的 Electron 人机五子棋。**机器棋手是真正通过 Pi Agent Harness 工具调用落子的 LLM**，不是将传统搜索 AI 包装成聊天界面。15 × 15 自由五子棋：黑先、连续五子及以上获胜、无禁手。

## 启动

需要 Bun、Node.js ≥ 22.19；桌面环境需要支持 Electron 45。

```bash
cd apps/five-llm            # 从仓库根目录进入
just five-llm               # 安装依赖、构建并启动；已装过依赖也可用 just start
```

关闭窗口、Cmd+Q 或 Ctrl+Q 都会结束应用，`just` 随之返回命令行，不会在后台残留。

### 连接 LLM

应用直接复用 Pi 的 `~/.pi/agent/auth.json`、`models.json` 和标准 provider 环境变量；支持 `PI_CODING_AGENT_DIR`。**不需要启动 Pi TUI，也不需要单独启动后端服务**。若尚未配置认证，可先在 Pi 中执行 `/login`，完成后退出并启动本应用。

默认选择 **`gpt-6.1-sol`**，优先使用 Pi 中已认证的 `openai-codex/gpt-6.1-sol`（本机已有该模型）。若默认模型不可用，会提示手动选择，**不会自动切换为 Claude 或其他模型**。

也可通过环境变量使用 API Key；需在 Pi 模型目录中有对应模型：

```bash
export OPENAI_API_KEY='你的密钥'
bun run start
```

OpenAI Codex 登录请使用 Pi `/login` 配置；它与 `openai` 的 API Key 认证属于不同 provider。其他提供商仍可从桌面手动选择。

在桌面下拉框选择已认证模型。可指定首选项（完整 `provider/modelId`，模型 ID 必须存在于本机 Pi 目录）：

```bash
FIVE_LLM_MODEL='openai-codex/gpt-6.1-sol' bun run start
```

本项目使用与本机文档一致的 **`@earendil-works/pi-coding-agent` 1.4.0**（Pi 新版包名），不混用旧 `@mariozechner` SDK。API 调用使用你的账户，可能产生费用。每次 Agent 运行最多 8 个模型回合、16 次工具调用，默认技术超时 90 秒（请求停止后比赛棋钟仍继续，不等同于棋局判负）。Pi 负责流式请求、工具调度和有限网络重试。需选用支持工具调用的聊天模型；模型强度和落子质量不保证。

### 本地 / OpenAI 兼容模型

在 Pi 的 `models.json` 添加支持工具调用的模型，例如：

```json
{
  "providers": {
    "local": {
      "baseUrl": "http://localhost:11434/v1",
      "api": "openai-completions",
      "apiKey": "local",
      "models": [{ "id": "qwen3:14b", "name": "Local Qwen", "contextWindow": 65536, "maxTokens": 4096 }]
    }
  }
}
```

API Key 只由主进程中的 Pi 使用，不发送给渲染器。模型列表在启动时读取；改变 Pi 认证或配置后，请重启应用。`models.json` 由 Pi 解析，其中的密钥命令属于可信的本机配置，请勿使用来历不明的文件。

## 比赛、计时与窗口尺寸

- 默认 **三局两胜**，在「新比赛 / 设置」中可选 **五局三胜**；胜负局之间交换黑白，和棋同色重赛、不计胜场。
- 默认每方每局 **10 分钟基本用时 + 3 × 60 秒日式读秒**：基本用时耗尽进入读秒；一次读秒耗尽只扣一次机会，最后一次耗尽才判本局负。
- 可选择 **包干制**，自己的累计局时耗尽即判本局负；或把基本用时设为 0，第一手起就执行读秒。
- 主进程权威计时，取消模型请求、重试、回看、打开设置均不停钟；LLM 网络等待也计时。90 秒 Agent 技术超时与棋局超时分开处理。
- 默认禁用比赛悔棋，可开启练习悔棋；已结算局不可悔棋。
- 布局按窗口宽高缩放；已验证 900、760、700 像素高窗口，无需整页上下滚动。

完整约定、例子及参考来源见 [RULES.md](RULES.md)。计时借鉴通用棋钟与围棋读秒，不宣称是所有五子棋国际比赛的统一规定。

## 四层架构

```text
┌─────────────────────────────────────────────┐
│ Electron 桌面层                            │
│ Canvas 棋盘、手记、回看、音乐、受限 IPC       │
└──────────────────┬──────────────────────────┘
                   │ 人类落子 / 新局 / 悔棋
┌──────────────────▼──────────────────────────┐
│ 业务层                                     │
│ 权威棋谱 → 全谱重放 → 胜负校验 → 局势计算   │
│ GameService → AgentDriver / TurnPort 接口   │
└──────────────────┬──────────────────────────┘
                   │ 棋谱 + 逐手评估摘要 + 当前候选
┌──────────────────▼──────────────────────────┐
│ Pi 扩展层                                  │
│ 分析 / 威胁 / 试算 / 验证 / 按需知识        │
│ place_stone → 证据与规则验证 → 业务层提交    │
└──────────────────▲──────────────────────────┘
                   │ 工具调用与结果
┌──────────────────┴──────────────────────────┐
│ Agent Loop 层：原生 Pi SDK                  │
│ createAgentSession + ModelRuntime           │
│ LLM ↔ 工具循环；非法落子可纠错；成功后终止    │
└─────────────────────────────────────────────┘
```

### 层与文件

| 层 | 路径 | 职责 |
|---|---|---|
| Agent Loop | `src/agent/pi-driver.ts` | 原生 Pi SDK 会话、模型认证、请求预算、取消与超时 |
| Pi 扩展 | `src/extensions/gomoku.ts` | 注入回合端口，注册七个受限工具、候选反证反馈与提交前验证 |
| 业务 | `src/business/rules.ts`、`tactics.ts`、`forcing.ts`、`decision.ts`、`clock.ts`、`game-service.ts` | 权威规则、启发式评估、决策信号/剧本路由、棋钟与比赛流程；`engine.ts` 保留兼容出口 |
| 领域知识 | `src/business/knowledge/`、`src/agent/knowledge-loader.ts` | 编排入口、原则索引、剧本与技能；宿主白名单加载，不开放通用文件读取 |
| 桌面 | `src/electron/`、`src/renderer/` | 安全 IPC、持久化、Canvas、交互、Web Audio |
| 跨层 DTO | `src/shared/types.ts` | IPC、状态快照和棋谱格式 |

业务层不依赖 Pi 或 Electron，通过接口注入 Agent。桌面主进程负责组合各层。渲染器使用同一纯规则模块回放历史，但**不能直接提交 LLM 落子或修改权威棋谱**。

### 每一手实际做什么

1. 业务层校验回合、坐标、占用、棋局是否结束。
2. 从完整棋谱重新重放全部落子，重新计算四个方向的成五结果。
3. 扫描所有空点的即时获胜与对手威胁；计算包含断点的五格窗口、活三、冲四、双三/双四，给出候选点与启发式分数。**分数不是胜率；不是完备博弈求解器。**
4. 逐手完整评估入本地棋谱；机器回合把完整棋谱、棋盘文本、逐手摘要及当前完整评估提交给 Pi。
5. LLM 必须先调用 `analyze_position` 或 `evaluate_threats` 获取证据，可按需读知识、试算最多六手或显式验证候选。普通中盘需对最终候选调用 `check_forcing_sequences`，检查对手连续冲四，并在下一次模型请求读到反馈后决定。未先检查就 `place_stone` 会返回 `accepted:false/needsReview`，不落子。模型可换子，或显式 `acknowledgeRisk:true` 保留有败势/未完成检查的合法候选，不会自动替换落点。当前立即胜负、开局和时间紧迫不强迫额外审查。最终提交仍扫描一手成五点，业务层再次校验棋钟、回合与 revision 后原子提交；只有 `accepted:true` 才停止同批后续工具和模型请求。
6. 每个机器回合使用一个隔离的内存 Pi Session，完整上下文来自业务棋谱，不依赖可能被压缩或残留的对话状态。

不会自行代下、不会解析模型自然语言坐标直接落子。无认证、无工具调用、网络失败、超时都会明确停止，提供继续/重试/换模型选项。取消、悔棋、新局都会使旧回合失效；迟到的请求不能改写新棋盘。应用不加载用户或项目的 Pi 扩展、技能、MCP 或编码工具，只开放七个五子棋领域工具；这不是操作系统沙箱。

## L3：知识如何成为推理信号

不再把规则、棋形建议与决策流程混在一段 system prompt 中：

- **硬规则**：`rules.ts` 执行合法性、重放和胜负；`clock.ts` / `GameService` 执行计时与提交，技能不能覆盖。
- **确定性事实**：`decision.ts` 输出全盘即时成五点、对手即时成五点和一步不可防信号；自身立即获胜优先于防守。
- **启发式**：`tactics.ts` 输出最多 12 个局部候选、窗口棋形和分数，明确不是胜率或深层必胜证明。
- **流程知识**：内置 5 条原则、4 个剧本和 4 项技能。每回合只注入入口、简短索引及选中剧本，其他全文通过 `read_knowledge(id)` 按需读取。
- **路由**：距丢失当前读秒/包干耗尽 ≤15 秒时使用时间剧本；否则有即时战术时使用收束剧本，再按前八手/其后选择开局或中盘。时间剧本仍须先处理即时胜负。
- **连续先手反证**：`forcing.ts` 只检查候选后对手的连续冲四，不负责选子。默认三次造威胁延伸、6000 节点、200ms，受棋钟与取消限制。结果为发现强制败势、预算内未发现或未完成；后两者都不是安全证明。
- **执行证据**：`notes[].decision` 使用 `gomoku-knowledge/v2`，保留剧本与四步进度；可选 `candidateReview` 保存每条候选绑定的试算/反证、revision、ID、预算、耗时和反馈请求边界。compare=done 只代表最终候选有单线试算或已返回到先前请求的反证，不代表穷举或模型理解。旧版 v1 记录仍兼容，不保存私有思维链。

工具：`analyze_position`（兼容完整分析）、`evaluate_threats`（结构化信号/时间快照）、`simulate_moves`（副本试算）、`validate_move`（只读候选验证）、`read_knowledge`（内置 ID 白名单）、`check_forcing_sequences`（有界连续冲四反证）、`place_stone`（审查反馈后验证提交）。不提供 Renju 禁手工具，因为本应用无禁手。

知识包随构建复制到 `dist/business/knowledge/`，不从会话工作目录发现技能。修改内置 Markdown 后重新构建并启动即可；不需改变 Pi 全局配置。原 `engine.ts` 导入保持可用，棋谱仍为 `five-llm/v1`，旧手记没有可选的 `decision` 字段也有效。详细设计、迁移与暂缓项见 [L3 重构说明](docs/l3-knowledge-refactor.md)；本轮候选反证与证据契约见 [连续先手检查](docs/forcing-review.md)。

## 桌面功能

- 木质纹理棋盘、黑白渐变棋子、手数、末手标记与胜利连线。
- 人类可执黑或执白；机器执黑时由 LLM 下开局。
- 候选点提示；方向键定位、Enter / 空格落子。
- 默认正式式样比赛不允许悔棋；可启用练习悔棋，不返还已用时间。支持取消模型请求、继续/重试，期间棋钟继续。
- 公开的简短 LLM 落子理由，不展示私有思维链。
- 点击棋谱或拖动滑块回看；回看时禁止落子，返回实战继续。
- 页脚可展开查看四层链路与工具日志。
- 背景音乐已移除程序合成，改为随应用附带的完整 MP3：萨蒂《Gymnopedie No. 1》及电钢琴 / 萨克斯《Night on the Docks - Sax》。默认暂停、12% 音量，播放与切换有淡入淡出，点击 ♫ 播放；无需联网。
- 两首录音由 **Kevin MacLeod (incompetech.com)** 提供，采用 **CC BY 4.0** 授权。音乐区 ⓘ 可查看署名；原始文件未改动，完整来源、授权链接及校验值见 [`ATTRIBUTION.md`](src/renderer/assets/music/ATTRIBUTION.md)。
- JSON 导出，包含完整棋谱、逐手计算、落子理由、时钟、终局原因及多局比赛比分摘要。

### 自动保存

棋局更新后串行原子保存至 Electron `userData/records/<game-id>.json`。macOS 默认是：

```text
~/Library/Application Support/Five LLM/records/
```

每盘使用独立 ID，不覆盖上一盘；最新一盘包含整场比赛 ID、比分和所有已完成盘的摘要。练习悔棋更新当前棋局文件。关闭窗口即退出应用；退出前停止棋钟并等待排队写入（最多 3 秒）。自动保存失败会明确弹窗。当前版本提供棋谱导出和**当前局回看**，尚无历史棋谱导入、跨启动续局或应用安装包签名。

```bash
just check                 # TypeScript + 规则/业务/Pi 集成测试 + 构建
just smoke                 # 启动真正 Electron，Playwright 验证桌面并截图
```

测试覆盖规则、棋钟边界、读秒耗尽、延迟通知、迟到落子拒绝、重试不返还时间、三局/五局比分与和棋重赛，以及知识包完整性、按需注入、剧本路由、结构化信号、候选验证与证据记录隔离。Electron smoke 额外验证三种窗口高度无整页溢出、赛制设置、认输、真实主进程超时结算，以及两首本地 MP3 的实际解码、播放进度、切换和署名弹窗。模型选择测试确保默认 `gpt-6.1-sol` 且缺失时不自动回退到 Claude。

Pi 集成测试用本地 OpenAI-compatible SSE 测试服务验证**真正 Pi Agent Loop** 的工具调度、非法落子纠错、知识白名单、证据门禁、同批工具提交后终止与取消，不访问外部模型，不消耗 API 额度。Electron smoke 使用显式 `FIVE_LLM_SMOKE=1` 的测试替身，输出在 `artifacts/`；正常启动绝不会走此分支。真实提供商的连通性仍需用你自己的认证实测。

构建产物位于 `dist/`，开发任务由 Bun / just 执行；不使用 TUI。
