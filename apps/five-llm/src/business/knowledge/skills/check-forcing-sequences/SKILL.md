# 连续先手反证

## 触发与输入

普通中盘、没有当前立即胜负且时间充足时，对最终候选执行；尤其理由是“下一步进攻/形成活四”时。输入为候选 x/y、当前 revision，可选 maxAttackMoves（1..4）、maxNodes（0..6000）、maxMs（0..200）。工具名 check_forcing_sequences，不是 read_knowledge 的文件路径。

## 执行

1. 先用 evaluate_threats 或 analyze_position 获取当前事实。先取自身立即胜，再处理对手立即胜，最后才考虑深入反证。
2. 调用 check_forcing_sequences(x,y,revision)，在副本上检查候选之后，对手能否通过连续冲四强制获胜。预算默认三次造威胁延伸、6000 节点、200ms；还受棋钟和取消约束。没有候选推荐或自动代下。
3. **found-forced-loss**：阅读 proof.line、winningPoints。检查每个唯一防点以及终点；重新比较另一候选，而不是继续假定对手配合原攻击计划。
4. **not-found-within-budget**：仅表示此范围没有找到连续冲四反证，不等于安全、必胜或最优。必要时继续用 simulate_moves 探索其他威胁。
5. **incomplete**：节点/时间/取消/棋钟预算不足；不得声称已检查安全。预算充足可重查，时间紧迫应及时作出明确选择。
6. 必须在下一次模型请求读到反馈后再提交最终候选；不要把检查和预先安排的落子放在同一批就当作已审查。若保留有败势或未完成检查的候选，显式 acknowledgeRisk:true；仍由业务层检查合法性和截止时间。

本工具只检查对手反杀，不寻找自己的胜法；先看观察结果 ownForcingWin，或调用 find_forcing_win。选中已返回先前请求的己方强杀证明起手时，无需重复反证。普通中盘其他候选未先检查就调用 place_stone，会返回 accepted:false、needsReview 和候选反证，**没有落子**。读反馈后再决定；只有 accepted:true 才表示成功提交。当前立即胜负、开局或时间紧迫时不强迫额外一轮审查，记录实际跳过范围。

## 案例与局限

真实局面中，白 H7 → 黑 I7 → 白 H6 → 黑 M11 → 白 L10 → 黑 L11，黑得到 I11/N11 两个成五点；白 H7 → 黑 I11 → 白 I8 的有利单线不能反驳前一条强制线路。

搜索只查连续冲四，不查完整博弈树、连续活三或全部战略反击。强制线路会考虑防守方能否先成五，不能把一条自选应手线包装成强制证明。证据绑定候选、revision、检查 ID、预算与耗时；不记录私有思维链。
