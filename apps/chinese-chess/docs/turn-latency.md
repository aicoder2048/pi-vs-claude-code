# 回合耗时诊断（不催促模型）

## 目标和边界

保持每方30分钟包干、thinkingLevel=low、16次工具调用及搜索/最终独立复查预算不变；模型请求总上限现为10次（8+2），最后2次仅提供落子/认输（详见[故障调查及预算调整](2026-10-31-request-budget-review.md)）；不增加单步截止时间，不记录内部推理和原始模型文本；timing本身不保存工具参数，白名单调用证据另见[调用审计](call-audit.md)。先测量，再决定是否优化模型或网络。

## 测量口径

- 起点：GameService创建机器回合；终点：成功提交事务落子前，或失败/取消/超时/替换时。不是从人类点击到动画结束的端到端延迟。
- model：Pi turn_start → assistant message_end（不是turn_end，后者包含工具）。包含网络、供应商排队、生成和SDK开销，不能拆称“纯思考”。一次Pi模型回合不等于一次HTTP尝试。
- firstDeltaMs：单次模型请求开始到首次text/thinking/toolcall增量的时间，只存时长、不读取内容。不是严格的网络TTFT，更不是思维链。
- tool：tool_execution_start → end。review是GameService独立提交复查（嵌套在move_piece内），pre-search是宿主自动预搜索；setup包含会话装配。
- 汇总按墙钟区间归属，review优先于tool；同类并发区间取并集，不重复累计；setup和未归类/重试间隔计入other。各项相加等于totalMs。原始span用于核对，不能再直接加总。
- 成功提交在notes[].timing随原子保存一次性落盘，不能等待tool_execution_end才补写。失败回合存attempts[]（只保留最近80项），取消时同步截断，旧回合迟到事件不得污染新回合。
- attempts变化即使revision未变也触发自动保存。运行中阶段仅为临时progress，不写入提示词或当成模型思考内容；updateSequence保证同revision的进度通知不会被迟到IPC回复倒退。

## 展示和优化

桌面显示“准备会话/预搜索/等待模型响应/接收模型响应/读取报告/比较候选/复核计划/提交复查”等可观察阶段。棋手手记旁展示简短耗时汇总，专家面板展示逐请求和工具数据；旧棋谱无timing时明确缺失，不推断为零。

本节描述历史耗时优化版本 xiangqi-skills/v2；当前已迁移到 [v3 原生 Skill](native-skills.md)，旧 v1/v2 记录仍可展示，耗时口径保持不变；当前请求预算以上述10次为准。技能指引优先使用已有signals和已覆盖的候选报告，需要全量字段才analyze_position；多个候选一次compare_moves，而非逐个重复review。允许必要时重算、继续搜索和读取，不强制限制思考、不自动代走、不跳过最终独立复查。

## 验证与使用

- `just check`：TypeScript、136项测试（0失败）和构建通过。
- `just smoke`、`bun run pack` + `just smoke-dist`通过；覆盖30分钟包干默认值、实时等待阶段、落子后耗时汇总、专家逐项详情、取消尝试实际自动落盘、重试与旧事件隔离，保留900/760/700高度无整页滚动。
- 本地SSE通过真实Pi会话验证模型/工具/预搜索/复查区间及首次增量；纯时钟单测验证互斥汇总、重叠区间、失败中断、80项上限、无revision变化的保存键、旧棋谱兼容。
- 在真实模型下对弈后，查看棋手手记的汇总及专家面板“回合耗时分解”，或导出JSON查看notes[].timing/attempts[]。先看模型请求次数，再看模型往返与工具/复查占比；首次增量高也可能是网络或排队，不能断定“模型想太久”。
- 此次未做真实供应商延迟A/B测试，UI fixture的合成耗时不作性能结论。技能指引是否减少实际调用、整体是否提速，需要相同模型和局面的实战记录验证。
