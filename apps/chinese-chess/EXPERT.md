# 业务层专家参谋与技能组 v1

目标不是让 LLM 背更多口诀，而是给它**局面事实、可验证的反击变化和有条件的棋理**。不接入外部棋力引擎，不自动代替模型落子。

入口：`src/business/expert.ts`。成型定式由 `knowledge.ts` 提供，赛后经验由 `learning.ts` 验证并召回，再由 GameService 组合到专家报告；见 [LEARNING.md](LEARNING.md) 与 [KNOWLEDGE-SOURCES.md](KNOWLEDGE-SOURCES.md)。复用 `engine.ts` 的全部走法及将帅安全规则；业务层不依赖 Pi 或 Electron。

## 1. 局面报告

每次实际走子及新局，业务层计算 `Analysis.expert`，并随逐手评估自动保存：

- **阶段**：大子总数不超过 6 视为残局；否则前 20 个半回合视为开局，其余中局。这是启发式分段，不是棋理定论。
- **子力**：车 900，士象 200，未过河兵卒 100 / 过河 180；开中局马 400 / 炮 450，残局马 450 / 炮 400。将帅不参加子力交换计分，胜负由规则裁定。
- **安全**：双方每枚非将帅棋子的合法吃子攻击者、几何保护者，以及离开原位是否暴露己方将帅。
- **协调**：士象剩余、将帅合法出口、未离底线车马、马的合法落点数量。
- **位置分解**（`evaluation.ts`）：有效出子、车炮通路 / 马腿活动性、九宫周边多子协同、九宫线牵制、近四次己方着法的无吃子 / 无将军往返。压力按几何计算，炮须有一枚炮架；不把几何控制当成合法吃子证明。不以将军次数或单纯前进加分，位置项远低于规则胜负。
- **威胁优先级**：先应将、核查直接杀棋和受攻击大子，再看吃子、出子与进攻。
- **专家规则**：按阶段和当前棋子触发，附证据与例外。包括失守、牵制、开局出子、反复动子、马腿与空间、炮架变化、九宫安全、残局协调，以及优势 / 劣势处理。

**几何保护不能充当合法回吃证明。** 马腿、炮架和牵制会变化；交换必须在走子后的棋盘上重新计算。将军信息依规则模块处理，不把“吃掉将帅”当成合法候选。

## 2. 候选审查

`reviewMove(position, move)`：

1. 用规则模块执行候选；直接将死 / 困毙 / 重复判负等规则结果优先于子力。
2. 生成对方合法应手，按吃子价值与将军排序，在预算内逐个检查。
3. 若发现对方一手即可使我方被将死、困毙或规则判负，返回**具体合法反例**。
4. 对对方吃子应手，继续计算该落点上的合法连续回吃，默认最多 6 次后续吃子。
5. 将本步吃子收益减去最不利的已发现交换损失；同时提供双方局面评价差的变化。报告预筛选混合吃子、受攻大子的安全撤退与位置候选，避免新位置项挤掉旧的防丢子候选。

输出包含：`risk`、`estimatedNet`、`bestReply`、`line`、`coverage`、`warnings`。风险分为终局获胜、直接败着反例、明显亏子估计、小幅交换风险、覆盖不足及未发现直接亏子。

**计分不是胜率。** 排序主要依据交换估计，位置分为次级因素；未完成检查的候选有不确定性折扣。不能以“将军”“主动”“靠近中路”等奖励掩盖送车。

### 同格交换的边界

这是有合法性约束的 SEE 类估计，不是完整 minimax / 静态搜索：允许双方放弃这个落点的交换，不能完整表达必须应将、异地弃子补偿、串联杀法或长期阵势。它提供一条实际可走的变化，但不证明对方必然选择这条变化，也不证明该变化是全局最优。

合法走法使用真实炮架、马腿、象眼及将帅安全，每一步都重新计算。深度或节点用尽时返回不完整标志，不把截断结果当安全证书。

## 3. 工具与模型流程

Pi 扩展只开放八个业务工具；不开放 read/bash 或任意文件路径：

| 工具 | 作用 |
|---|---|
| `analyze_position` | 权威棋盘、全部合法走法及已计算的专家报告 |
| `search_position` | 对全部合法走法或指定 1–6 个候选作有界多步对抗，返回完整深度 / 覆盖 / 主变化 |
| `review_move` | 针对任意合法候选审查，不局限报告里的候选集 |
| `compare_moves` | 公平分配预算，比较 1–6 个候选的对方反击 |
| `simulate_moves` | 验证模型指定的 1–6 手变化，附终局和专家评估；不保证这些是对方最强应手 |
| `update_plan` | 暂存继续 / 修订 / 放弃的公开条件计划，只随成功落子保存 |
| `move_piece` | 异步最终提交，业务层再次独立进行交换与多步复查 |
| `read_skill` | 仅按 enum 名称读取自带技能或安全 references 文件，计入工具预算 |

模型流程的唯一事实源为 [入口技能](skills/xiangqi-coach/SKILL.md)、[六条原则](skills/principles/)、[七份剧本](skills/playbooks/) 与 [专项技能](skills/skills/)。字段和原则全文见 [报告参考](skills/skills/read-expert-report/references/)，界面与模型使用同一 Markdown。请求模型前仍自动进行一次全合法根搜索。

宿主 `decision.ts` 确定性路由：终局不启动；应将 > 时间压力 > 己方大子受合法攻击（价值 ≥400）> 阶段。时间阈值为 max(60秒, 近期8次机器平均用时×3)，包干额外至少90秒。它是启发式路由而非走法强制；初始局面也可能有隔子炮攻击马，受攻不等于失子。

Pi 1.4.0 原生发现/校验19项应用技能，`noSkills + additionalSkillPaths` 排除用户/项目资源。常驻只有入口、11项可见索引及唯一当前剧本；其他按需读。索引路径为逻辑相对路径；reference 只接受平面文件名，同时校验 realpath 防越界。首条用户消息用紧凑 signals，完整报告由 analyze_position 按需返回；历史摘要保留最近20手及吃子手，不改变权威分析和棋谱。

`notes[].decision` 当前记录 xiangqi-skills/v2（旧记录v1仍可读取）、revision、当前剧本、分别记录的注入与读取、含失败调用的顺序工具序列、四步 done/skipped 及公开证据。成功 commit 在业务保存事务中计入，避免 tool_execution_end 晚于自动保存；旧棋谱字段可缺省。它记录行为证据，不保存内部思维链，不证明模型认真遵循技能或棋力提升。

`plan.ts` 保存目标、当前问题、对方计划、1–3 项近期步骤、放弃条件和复核说明。对方走子后标记需复核，将军、对方吃子、8 半回合过期或终局使计划失效；失效计划不可直接 continue，必须 revise。悔棋、换模型、新局 / 下一盘清空。更新只在本回合暂存，成功落子才保存到状态、逐手理由和棋谱；取消、非法或被拒绝的提交不污染旧计划。旧计划永不自动执行走法。

### 耗时诊断与公开阶段

`notes[].timing`（xiangqi-timing/v1）在成功提交事务内保存完整耗时；失败整回合存 `attempts[]`（最近80项）。取消/超时/换局同步封口，旧回合迟到事件不污染新局，失败但revision不变时也会原子保存。运行中progress与通知顺序号不进入模型提示词。

模型区间用Pi turn_start到assistant message_end，不能用包含工具的turn_end。首次text/thinking/toolcall增量只记时长，不读写内容；包含网络、排队和生成，不伪称纯思考或网络TTFT。工具区间包含审查时，汇总将独立复查单列扣除；并发区间取并集。每项相加等于总时长；SDK准备和重试空隙计入其他。详见 [测量口径](docs/turn-latency.md)。

v2技能复用同revision的已有signals与搜索；多个缺证据候选一次compare_moves，不例行重复analyze_position。必要时仍可追加读取/搜索。thinkingLevel、8请求/16工具、搜索与独立复查预算不变，不催促、不加单步时限，不保证真实模型响应加速。

## 4. 提交时的业务防臭棋检查

不依赖模型自愿调用审查工具。`GameService` 的回合端口每次提交都会复查：

- 发现直接败着反例，或交换估计净亏至少 250 分，先返回风险和反驳变化，**不提交、不切钟、不修改棋谱**。
- 模型可以改选其他棋。
- 若模型认为有具体弃子补偿，或败势确实不可避免，可填写 **12–400 字的 `riskAcknowledgement`** 再提交。说明、复查结果和公开落子理由一并保存。
- 这不是证明补偿有效的机制，也不是硬性禁止弃子。它让模型显式面对风险，保留模型最终选择；不会自动替换为业务层排名第一的棋。
- 非法、过期、重复或超时提交仍不可用风险说明绕过。
- 复查后再次核对棋钟，计算期间超时同样不能落子。
- 最终实际走法还会独立通过 `SearchDriver` 搜索，不依赖模型是否调用工具、是否只搜索其他候选。只有完整迭代产生败局级根分且主变化可合法重放到判负，才升级为多步败着风险；保留原同格交换估计，不能用浅层位置分洗掉已发现的送子。
- Worker 失败、零预算或未完成根节点明确标为未知；仍执行旧的单步审查，不编造安全证明。SDK 工具取消和棋钟耗尽 / 棋局失效信号一同传到搜索，异步复查结束后再验有效性，拒绝迟到与并发提交。
- 每方默认 30 分钟包干、不加秒，不另设单步时限，已移除固定 90 秒技术超时；长考、网络和工具计算都由剩余棋钟统一计时。每回合最多 8 个模型回合 / 16 次工具调用及独立搜索预算仍保留，作为资源保护，不是单步时间限制。

## 5. 性能与覆盖

默认局面报告最多详细审查 12 个候选，混合吃子候选与位置发展候选；**不是对全部合法走法完整搜索**。完整合法走法可通过 analyze_position 按需读取，模型可另行审查任意候选。

战术枚举默认 5000 节点、80ms 的协作式预算，统计的节点是对手应手 / 交换节点。初始规则生成、合法性验证、子力关系与位置预筛选不计入这个节点数，预算不是硬实时上限。候选之间分配剩余预算；比较工具总预算默认 6000 节点 / 120ms，按候选等分。

终局判定使用“找到一个合法应手即可提前停止”的优化，保留规则语义，减少浅层展开成本。所有分析为纯函数，不读写权威棋盘；实际提交仍经业务端口。

本机 Bun 对这盘棋的 71 个走子前局面做默认分析，测得平均约 4ms、峰值约 29ms；这是一次本地观测，不是硬实时保证。

## 7. 多步搜索预算与边界

`search.ts` 采用迭代加深 negamax / alpha-beta、将军和唯一应将延伸、吃子与合法应将静态搜索；不在被将军时使用静态停着估计。每个根以独立窗口评分，只采用最后完整迭代。没有跨不同重复历史的置换表，不忽略真实重复 / 长将 / 无进展规则。

`live-search.ts` 按九宫压力与余时分配预算。每次 Agent 尝试总计最多 2600ms / 70000 节点，工具搜索预留提交审查的 700ms / 20000 节点；单次通常 550ms，危险时 900ms，最多 1000ms / 30000 节点，且不超过当前余时的 1/12。最终单候选默认至多 700ms / 20000 节点、深度上限 5（工具最多 6），深度是上限而非完成保证。桌面通过 Worker 注入，启动 / IPC 也计入时间；硬看门狗额外允许 150ms 清理余量。纯业务嵌入的默认后备为同预算同步计算，不应在需要保持 UI / 心跳响应的宿主中代替 Worker。

报告保留 `completedDepth`、`attemptedDepth`、`rootScope`、`nodes`、`stopped`、`horizonCuts` 和 `limitations`；不是胜率或完备求解。主变化是一条最佳变化展示，不是单独的强制性证明；有界搜索也存在地平线。

## 暂未实现

专业引擎级深度、完备的复杂杀法求解、完整大规模开局库、残局库、完整长捉裁判和外部象棋引擎。当前局面权重与计划流程需要通过固定预算、红黑交换的实战评测继续校准，不能只看模型解释是否像高手。
