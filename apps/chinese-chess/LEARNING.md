# 成型知识 + 赛后经验：正式辅助闭环

本版本把两条线结合，而不是只等用户犯错：

```text
公开定式 / 棋理 → 带来源的结构化知识包 → 局面匹配 + 当前战术复核 ─┐
                                                               ↓
实际对局 → Worker 复盘双方 → 样本独立验证 → 持久化案例库 → 按需检索 → LLM 自主决策
                       ↑                                      ↓
                       └──────────── 下一盘继续验证与纠错 ───────┘
```

这是本地经验检索与业务知识辅助，**不是模型权重训练，不自动提高所有局面的棋力，更不把历史赢棋当作每步正确的标签**。

## 一、成型知识是基础，不等人工案例积累

`src/business/knowledge.ts` 内置首批 **12 条开局示例路线、79 个路线节点（包含重合局面）**：中炮对屏风马、五六炮过河车、反宫马、顺炮、列炮、飞相、仕角炮、过宫炮、仙人指路和对兵等。参考网上已核对的 ECCO 分类及公开棋理，着法坐标自行编码，说明自行撰写。

- 每条路线逐步通过本项目规则重放，非法数据不能静默加载。
- 用**全盘棋子分布 + 行棋方**匹配，不凭开局名称或文本相似度背谱。
- 支持左右镜像、旋转换色、殊途同归的相同局面；**不是完整 ECCO 分类器**。ECCO 的顺序型 / 过程型分类不能全部简化成局面查表。
- 只有当前局面完全匹配，且候选经本地反击 / 交换复查后，才提供示例着法。
- 路线终点只提供计划和例外，不编造后续定式。
- 偏离路线后不硬套；开、中、残局的条件棋理仍可按局面触发。
- 返回 `source`、`applicability`、`caution`、`verification`，明确区分建议与当前验证结果。
- 默认每个局面最多 5 条知识提示，优先提供少量相关内容，不把整本棋书塞入提示词。

资料来源、授权边界、云库与引擎评估见 [KNOWLEDGE-SOURCES.md](KNOWLEDGE-SOURCES.md)。运行时不抓网页、不执行远程文本、不向知识网站上传棋谱。

## 二、对局结束后自动复盘

终局记录成功原子保存后，主进程把**棋局 ID**发送给独立 Node Worker。Worker 自行读取棋谱并分析，不传主进程的密钥或 Pi 会话。启动时也会扫描历史已结束记录，回填没有复盘过的棋局。

- 双方每一手都重新验算，不依赖旧版本保存的候选分数或模型解释。
- 无论人类赢还是大模型赢，都检查双方失误。
- 未结束的新局 / 中断局不自动学习；下一局只走一手不会污染案例库。
- 格式、坐标、完整重放和终局原因均校验；非法棋谱不会被当成经验。
- 已处理标识按**规则/验证器版本 + 规范化着法 + 执棋方 + 终局 + 明确接受风险的手数**计算。仅退出时钟变化不触发重新学习。
- 已结束的空棋局（例如未走子即超时）可以有一份零样本复盘，不因此生成战术知识。

## 三、什么样的样本能入库

先用当前业务审查找出：对方有一手取胜反例，或交换估计净亏至少 250 分的候选。随后独立验证：

1. 原始历史、失误走法、反驳变化都可合法重放。
2. 当前分析的应手和交换覆盖完整，而非预算截断。
3. 证据是以下一种：
   - 对方这一手确实导致规则判负；
   - 对方合法吃子，当前没有同格立即合法回吃，形成可验证的局部失子事实。
4. 找到至少一条经相同分析验证的较安全替代：不直接败、不再出现 250 分以上损失；普通失子样本还须较原走法改善至少 100 分。
5. 模型已经明确说明接受弃子风险的走法保留为候选，**不自动强化“弃子就是错误”**。

以下都不自动进入推理案例库：只有低分、没有具体反驳、没有较安全替代、局面已经无可避免地大失子、覆盖不足，或只根据最后胜负推断的“经验”。

**“已验证”指局部事实，不是全局最优 / 强制败局的证明。** 同格交换仍不覆盖异地弃子补偿和所有强制杀法；即使入库，也必须随提示保留这些边界。

### 避免失误与抓住机会是两道题

同一个样本可用于：

- 失误之前的局面：提醒当前方不要走出同类失误。
- 失误之后的局面：提醒另一方核查具体得子 / 一手取胜机会。

“实战抓住机会”只在实际下一手与验证反驳相同的时候计数。实际应手不同不自动标成错失，因为可能存在同样好或更好的其他应手。

## 四、库的去重和恢复

保存位置是 Electron `userData/learning/library.json`；macOS 默认：

```text
~/Library/Application Support/Chinese Chess LLM/learning/library.json
```

- 案例 ID 使用全盘局面、失误和反驳的镜像 / 旋转换色规范化信息做 SHA-256 标识。
- 重复样本合并出处（每案例最多展示 / 保留 32 个不同来源），不重复灌入。
- 案例、复盘报告和已处理指纹在**同一事务文件**中原子替换，避免“已标记学习，但案例没保存”。
- 写入有进程锁并在锁内重新读取；应用和 CLI 同时回填不会相互覆盖。
- 写前保留一代 `library.json.bak`；无效 JSON 不会被空库静默覆盖。
- 启动重新验证案例的坐标证据，重新生成标题、分数和说明；磁盘里的任意说明不能直接进入模型。
- 非法或重复的磁盘案例会过滤并报告；有合法结构的文件在下一次事务前备份。
- 中途关闭时取消未完成复盘；没有提交的任务不写完成标记，下次启动从原棋谱重做。
- 原始 `records/*.json` 不改写、不删除。学习库可在保留原棋谱的情况下重新构建。

当前资源上限：每棋谱最多 600 半回合 / 16MB，扫描前 2000 个 JSON 文件；最多 500 个案例、1000 份复盘报告，库不超过 32MB。达到上限并不意味着所有更大数据集都已学习；需要扩展存储时应改为索引数据库。原始记录始终保留。

## 五、按需注入，不盲从旧棋谱

每个实际回合的 `Analysis.expert` 增加：

- `knowledge`：来源可追溯的定式和条件棋理。
- `experiences`：从已验证案例中召回并按当前局面重验的少量提示。

案例检索先做完整局面匹配，再考虑同类战术：

- 精确匹配：重新验算映射到当前棋盘的失误或惩罚走法，重新考虑当前重复历史和规则。
- 相似匹配：必须已经有**当前计算出的同类反例或得子变化**；只按标题相似不能推荐历史着法。
- 每次最多返回 3 条提示。未命中不强行附会。
- 当前走法与历史变例分开标注，模型被要求只用 `currentMove/currentLine` 指导这一步。
- `review_move` / `compare_moves` 也能针对非首选候选检索经验。
- 所有提交仍经过原有规则、版本、棋钟和独立专家复查。知识不自动代下、不绕过验证。

## 六、使用与验证

界面「专家参谋」查看当前定式、来源、案例和战术复核。「复盘 / 案例库」查看后台进度、最近复盘、双方局部失误、具体反驳和候选状态；「回填已有棋谱」可以重新扫描。

命令行可不启动 Electron、不联网回填：

```bash
cd apps/chinese-chess
just learn
# 或指定 Electron userData 目录
bun run learn '/path/to/Chinese Chess LLM'
```

原有两盘实战已回填，得到 11 条局部验证案例，另有未晋升的候选；第二盘的人类第31、49手进入库，模型明确接受的第46手弃子未自动入库。原始棋谱字节校验未改变。

测试包括：真实双方失误、弃子保护、错误证据拒绝、较安全替代、镜像去重、换色召回、无关局面不注入、持久化恢复、重复运行幂等、并发写入、损坏文件、历史回填、原谱保持、模型回合快照注入，以及所有示例路线与偏离路线的处理。真实 Electron smoke 验证后台 Worker、复盘界面和案例保存。

## 七、还应该怎么做

下一阶段建议按收益排序：

1. **扩充有合法使用依据的成型定式**：给每条路线配置位置、计划、陷阱、证据、出处和覆盖边界。当前 12 条是起步包，不是完整百科。
2. **加入预算受控的对抗搜索**：迭代加深、将军/唯一应将延伸、吃子和应将静态搜索，继续放 Worker；优先解决两三手抽子和反将，不拍脑袋保证固定深度。
3. **建立固定战术评测集**：漏一步杀、丢大子、正确弃子被误拦的比例，以及延迟 / API 成本；同题对比旧版和新版，不能拿解释流畅度或案例数量当棋力。
4. **审慎加入残局资料**：将帅协同、兵卒、士象堡垒及兑换边界；名称和子力数量不够，须完整条件或验证过的残局表。
5. **可选云库 / 引擎辅助**：必须用户明确启用，注明引擎/云库来源、隐私和规则差异；不能把它们的分析全部算成 LLM 自身能力。
